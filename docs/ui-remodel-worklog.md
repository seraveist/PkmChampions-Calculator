# 전체 UI 리모델링 작업 기록

## 사용자 확정 기준

- `samples/calculator/`의 최종 모습이 디자인 기준이다. 스마트 로토무 색상, 라이트·다크 테마를 유지한다.
- 간결한 한 줄 목록, 노력치·랭크 상시 표시, 접이식 필드 설정, 공통 화살표·선택창·글자 위계를 사용한다.
- 포켓몬 선택은 이름 고정 열 → 타입 2개 → 종족값, 기술은 이름 → 타입 배지 → 굵은 위력 → 분류 → 설명, 성격은 이름 → 상승 → 하락이다.
- 모든 메뉴를 실제 본편에서 개편하고, 메뉴마다 HTML/참조/CSS/우선순위/중복을 검토한다. 마지막에는 공통 요소의 소유권과 계층까지 검증한다.
- 기능과 상태 계산, 저장 파티, 메뉴 간 전달을 유지한다.

## 구조 결정

1. `RotomUI`와 `uiStatTable()`가 같은 아이콘·입력·선택 트리거·능력치 표를 제공한다.
2. 기존 상태/계산 계약을 유지하고 렌더링을 교체했다. 역계산 Worker에서 UI 렌더러를 분리했다.
3. 기존 CSS 위에 규칙을 덧붙이지 않고 공통 부품과 메뉴 배치의 소유 파일을 교체했다. 늦게 덮어쓰던 스타일 파일을 제거했다.
4. 검색 선택창은 `uiWirePickerDialog()`로 모았다. native dialog, 키보드, IME, 포커스 복귀, 고정 열과 행 높이를 공유한다.
5. 메뉴별 상태·브라우저 검사 이후 전체 구조·화면·기능 검사를 수행했다. 이전 외형에 의존하던 검사는 새 구조의 동일 기능·접근성 계약으로 갱신했다.

## 검토 중 수정한 결함

- 첫 진입 시 세부조정·역계산 전달이 지연 로딩보다 먼저 실행되는 문제를 수정했다.
- 도감에서 빈 계산기 측으로 전달할 때 오래된 DOM을 갱신하다 실패하는 문제를 수정했다.
- 선택 후 변경된 값으로 포커스 대상을 찾지 못하는 문제를 수정했다.
- 수동 타입 초기화와 배지 갱신, 파티 팝업 중앙 배치와 작은 화면 헤더를 수정했다.
- 계산기 전용 파일에 남아 있던 공통 제목·참가자 색상·행동 버튼 스타일을 공통 소유자로 옮겼다.
- 후속 사용자 제보로 도감 표에 잘못 연결된 버튼 클래스를 제거했다. 고정 헤더·이름 열의 실제 스크롤/터치 드래그 위치 검사를 추가했고, 메뉴 탭도 샘플의 동일 폭·간격으로 맞췄다.
- 세부조정·상성표·도감의 폰트를 실제 표시값으로 대조했다. 중첩된 굵기 900과 작은 비교 수치를 수정하고 데이터 표의 글자 위계를 공통 소유자로 통합했다.
