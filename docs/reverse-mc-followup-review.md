# 역계산 재분석 — 한 턴 관측에서 다음 행동까지

구현 결과와 최종 적용 범위는 [내구 역계산 리빌드](reverse-rebuild.md)를 참고한다. 아래 내용은 리빌드 전 재기획 검토 기록이다.

2026-09-09, `46b1a13` 제품 소스 기준. 사용자가 구체화한 다섯 단계와 결과 카드 중심의 판단 방식에 맞춰 검토 범위를 수정했다. 별도의 행동 추천은 추가하지 않는다. 제품 코드는 변경하지 않았다.

## 목적과 범위

싱글 63 대면에서 실제로 관측한 한 턴의 정보로 상대의 대략적인 형태를 추정하고, 현재 남은 HP에서 내 기술로 상대를 잡을 수 있는지와 내가 먼저 쓰러지는지를 판단한다. 내 포켓몬의 성격·노력치·도구·기술 배치는 이미 설정한 정보를 사용한다.

1. 상대 포켓몬, 양쪽 시작 HP, 시작 랭크를 설정한다.
2. 실제 한 턴의 선후공, 내가 쓴 기술과 상대 잔여 HP %, 상대가 쓴 기술과 내 잔여 HP 실수치를 입력한다.
3. 상대 도구를 관측했다면 선택하고, 관측하지 못했다면 미확인으로 둔다.
4. 이 관측과 양립하는 형태를 추정한다. 내구는 H32 우선, 추가 내구가 필요하면 B/D를 배분하는 기준을 유지한다.
5. 추정 후보별 결과 카드에서 다음 턴 시작 상태, 선후공, 내 기술과 관측한 상대 기술의 대미지 범위를 제공한다. 다음 행동은 사용자가 판단한다.

레드카드·탈출버튼 등으로 대면이 바뀌면 사용자가 새 관측을 시작한다. 교체 대상, 교체 후 피해, 대전 이력, 이후 여러 턴을 이어 계산하는 기능은 필요 범위에 넣지 않는다. 기존 진단에서 발견한 모든 상태 전이를 완성해야 이 메뉴를 사용할 수 있다는 이전 우선순위는 철회한다.

## 필요한 계산의 경계

관측한 최종 HP를 설명하려면 직접 피해 보정과 관측한 회복·열매의 효과는 계산에 남아야 한다. 예를 들어 먹다남은음식 회복 후 HP를 입력했다면, 회복량을 포함해 해당 후보가 관측값과 맞는지 확인한다. 사용자가 회복 전 HP나 실제 회복량을 따로 계산해 입력하게 하지 않는다.

미관측 도구는 없음과 다르다. 다만 모든 도구의 발동·교체·이후 턴을 재현하는 것은 필요하지 않다. 현재 관측의 피해와 선후공에 영향을 주는 가능한 도구를 중심으로 후보를 구성한다. 현재 기본값은 없음·구애스카프·상대 타입 강화 도구로 제한되어 있어 이 부분은 보완할 가치가 있다.

이미 입력한 기술이나 도구만으로 알 수 있고 바로 다음 KO·생존을 바꾸는 효과는 내부에서 필요한 만큼 반영한다. 아직 계산하지 못하는 효과가 결론에 영향을 주는 경우에는 해당 기술의 확정 판단을 제한한다. 이를 해결하기 위해 모든 예외 상태 입력과 전투 시뮬레이션을 추가하지 않는다. 교체로 끝난 관측은 초기화로 처리한다.

기합의띠 발동 후 HP 1인 상대의 내구 추정은 기존 합의대로 제외한다.

## 형태 추정과 결과 카드

형태 결과는 대표 성격·배분과 함께, 해당 한 턴에서 좁힐 수 있었던 공격·내구·속도 범위를 보여 주는 것이 적절하다. H32 우선 기준을 유지하며, H32보다 낮은 HP에 B/D를 투자한 모든 배분을 별도 전수 검사하는 기능은 이번 필수 보완에서 제외한다. 따라서 행동 결론에는 ‘H32 우선 추정 후보 기준’이라는 범위를 표시한다.

결과 카드가 제공할 정보는 네 가지다.

1. **다음 턴 전 상태 변화:** 관측 공방 중 발동한 특성과 턴 종료 효과를 반영한 최종 랭크·HP·도구 상태를 보여 준다. 발동 원인과 변화량을 함께 표시한다. 이미 반영한 변화가 수동 랭크 입력으로 중복 적용되지 않도록 한다.
2. **다음 턴 선후공:** 변화 후 속도와 필드·도구·기술 우선도를 사용한다. 내 선공, 상대 선공, 동속, 후보에 따라 달라짐을 구분한다. 우선도가 다른 기술 조합은 해당 기술 기준의 순서를 표시한다.
3. **내 기술의 대미지 범위:** 각 상대 추정 형태에 대해 내 기술 배치의 피해 실수치와 %를 보여 준다. 현재 잔여 HP와 비교한 확정/난수 KO 표시는 판단 보조로 유지할 수 있다.
4. **상대 관측 기술의 대미지 범위:** 확인한 기술만 동일한 기준으로 표시한다. 관측한 기술이 하나면 하나만 표시하며, 추가로 알고 있는 기술을 표시하기 위해 여러 턴의 피해 관측이나 전투 이력을 요구하지 않는다. 피해를 관측하지 않은 공격축은 아직 좁혀지지 않은 범위를 사용한다.

대미지 범위의 표시 기준은 ‘다음 턴 시작 상태에서 해당 기술이 적중할 때’로 명시하는 것이 적절하다. 잔여 HP를 초과하는 피해도 그대로 표시하고, 먼저 쓰러져 행동하지 못하는 조건은 대미지 0과 혼동하지 않게 구분한다. 이후 턴의 전체 공방을 자동 진행하는 기능으로 넓히지 않는다.

현재 코드에서 확인한 보완 지점은 다음과 같다.

- `rcAdvanceAttack()`에는 지구력의 피격 후 방어 상승 처리가 있다. `rcEndOfExchange()`에는 가속의 턴 종료 속도 상승 처리가 없다. 피격 시점과 턴 종료 시점의 변화를 구분해 최종 상태로 연결해야 한다.
- 현재 랭크 패널은 자동 변화에 더하는 수동 보정 입력이며, 발동 원인과 계산에 사용한 최종 상태를 요약하는 표시가 필요하다.
- `rcHitOutcomes()`는 피해를 잔여 HP로 제한하고, `rcForecastHit()`는 먼저 쓰러져 행동하지 못하면 피해 0을 반환한다. 이 공방 결과가 현재 카드의 피해 범위에도 사용되므로, 카드에 필요한 기술 자체의 피해 범위와 구분해야 한다.
- `rcFormatDamage()`는 %만 표시한다. 내부 실수치 범위도 함께 보여 주면 내 잔여 HP와 직접 비교하기 쉽다.
- 현재 상대 기술 표시는 `predictedOppMove` 하나를 선택하는 구조다. 사용자가 확인한 기술들을 카드에서 비교할 수 있도록 정리하되, 미관측 기술을 자동으로 관측 목록에 넣지 않는다.

카드 안에서는 해당 후보 그룹의 실제 구성원을 사용해 범위를 계산한다. 기존 전체 후보 요약을 유지한다면 대표 후보 하나를 전체의 확정 결론으로 사용하지 않는다. 난수 때문에 결과가 달라지는 경우와 후보 형태 때문에 달라지는 경우를 구분해 표시하면 충분하며, 추천 행동·추천 이유·추천 순위는 필수 기능에서 제외한다.

후보 개수나 추천 점수를 상대 형태의 실제 확률로 표시하지 않는다. 후보 전체의 결론 일치도 역시 탐색 밖 형태까지 포함한 실전 성공률은 아니다.

## 입력 오차와 새 관측

현재 `rcObservedHpMatches()`는 상대 HP를 정수 % 하나에 엄격히 대조한다. 사용자가 HP 바를 대략 읽는 경우까지 지원하려면, 정확히 일치하는 후보가 없을 때 작은 주변 범위를 확인하고 ‘HP 근사 일치’로 구분하는 보완이 적절하다. 새로운 오차 입력을 필수로 요구하지 않으며, 근사 후보를 정확한 관측 일치로 표시하지 않는다. 오차 범위를 바꾸면 행동 결론이 달라지는지도 검증해야 한다.

상대 선택 변경 코드는 상대 기술과 일부 도구 정보를 초기화하지만 기존 잔여 HP·선후공·시작 HP·시작 랭크를 모두 비우지는 않는다. 결과 자체는 입력 변경 감지를 통해 무효화하는 장치가 있다. 문제는 새 관측에 예전 입력값이 남아 다시 계산될 수 있다는 점이다.

‘새 관측’은 내 기본 배치를 보존하고, 기존 관측 HP·사용 기술·선후공·도구 관측·추정 결과를 정리한다. 새 대면의 시작 HP와 랭크는 새 관측의 값으로 입력한다. 진행 중이던 이전 분석도 취소해 이전 결과가 뒤늦게 표시되지 않도록 한다. 교체 발동을 자동 감지하거나 다음 참가자를 계산할 필요는 없다.

## 수정한 보완 순서와 완료 기준

1. 다섯 단계에 맞춰 시작 상태와 관측 입력을 정리하고 새 관측 초기화를 제공한다.
2. 관측 도구 처리와 미확인 후보 구성을 사용자 추가 조작 없이 연결하고 HP 근사 입력으로 후보가 부당하게 사라지는 경우를 줄인다.
3. 공방 중 및 턴 종료 상태 변화를 다음 턴 시작 상태로 연결하고, 후보별 선후공과 양쪽 기술의 실제 대미지 범위를 결과 카드에 정리한다.
4. 알려진 형태의 관측 사례로 대표 추정, 후보 누락, 상태 변화의 누락·중복, 선후공·대미지 범위, 잘못된 확정 처치·생존, 새 관측에 이전 정보가 섞이지 않는지를 검증한다.

완료 기준은 한 턴의 입력만으로 대략적인 형태와 위 네 가지 카드 정보를 얻고 사용자가 다음 행동을 판단할 수 있는지다. 모든 형태를 특정하거나 모든 전투 예외를 재현하거나 행동을 자동 추천하는 것은 완료 조건이 아니다.

이전 통제 실험에서는 실제 형태가 15/15 조건의 후보 안에 남고, 다음 기술 비교 30개 중 24개에서 후보 전체의 KO·생존 결론이 일치했다. 같은 엔진으로 만든 소수의 합성 사례이므로 가능성을 보여 주는 자료이며 실전 정확도로 해석하지 않는다. 이전 검토는 `reverse-confidence-review.md`를 참고한다.

M-C 효과 진단 원자료 `reverse-mc-followup-probes.json`과 재현 스크립트 `scripts/reverse-mc-followup-review.mjs`는 기술 참고 자료로 남긴다. 여기에 담긴 모든 효과의 구현을 이번 메뉴 보완의 선행 조건으로 삼지 않는다.
