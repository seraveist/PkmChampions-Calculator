# 포켓몬 챔피언스 계산기 · 수정 후 프로젝트 재검토

이 문서에 남겼던 브라우저 검증·구조·성능 항목의 실행 결과는 [후속 개선 보고서](project-followup-2026-11-25.md)에 기록했다.


2026년 11월 25일. 기준 커밋 `676b364d6b876621683b195350334f6a84cc572f`에 앞서 작업한 샘플 구축용 KO 수정과 이번 프로젝트 검수 수정분을 적용한 로컬판이다. 게임 데이터와 참조 시뮬레이터의 기준은 Pokémon Showdown `f1040ecb5f5dba252e0e351e392dc409a5089ace`다. [수정 전 역기획서](project-reverse-spec-2026-11-25.md)와 [계산 목적별 판정 기준](damage-purpose-review.md)을 함께 참고할 수 있다.

## 결론

샘플을 만들고 저장하는 흐름에서 재현된 피해 편차와 파티 유실을 수정했다. 같은 포켓몬을 세부조정에 보내거나 두 탭에서 다른 슬롯을 수정하는 일상적인 사용이 검증의 중심이다. 다섯 메뉴와 저장 기능은 기기에서 실행된다. 별도의 API 서버나 중앙 DB를 추가할 근거는 발견되지 않았다. 출시 여부를 판단할 때 남은 가장 큰 확인 항목은 실제 브라우저 환경에서의 조작과 저장이다.

## 제품 동작과 수정 근거

| 영역 | 수정 또는 확인한 동작 | 관찰 및 검증 방법 |
|---|---|---|
| 계산기 ↔ 세부조정 | 날씨·필드의 설정 주체와 원래 값, 등장 특성 자동 적용 선택을 양방향으로 전달한다. 직접 선택한 필드와 양측 자동 필드를 구분한다. | 잔비 패리퍼를 날카로운눈으로 바꾼 뒤 파도타기 피해는 직접 변경과 세부조정 왕복 모두 46–55 HP였다. 수정 전 왕복 결과는 69–82 HP였다. 비·필드의 복원과 양측 방향도 상태 회귀로 확인했다. |
| 파티 저장 | 파티명과 멤버 슬롯 단위로 다른 탭의 편집을 병합한다. 같은 항목의 충돌은 확인 후 최신 값을 다시 읽는다. 저장 실패 시 현재 탭에서 백업할 수 있다. | 두 창이 저장한 이름을 모두 보존했다. 같은 슬롯의 취소·재충돌, 저장 용량 오류, 과거 JSON 형식, 손상·미래 버전 원본 보호를 검사했다. |
| 가져오기와 되돌리기 | JSON은 전체 파티, Showdown 텍스트는 지정 파티의 멤버를 교체한다. 텍스트 가져오기 되돌리기는 해당 멤버 목록에만 적용한다. 인식하지 못한 원문·포인트 보정·슬롯 초과 항목을 안내한다. | 다시 연 탭에서 한 파티의 가져오기를 되돌려도 이후 바꾼 파티명과 다른 파티의 편집이 유지됐다. 유효 슬롯이 기존과 같거나 모든 종명이 틀려 교체할 내용이 없는 경우에도 입력창에 진단이 남는다. |
| 샘플 저장 | 계산기 공격·방어 패널의 ‘파티에 저장’이 기존 슬롯 선택창을 연다. 빈 슬롯에 저장하거나 확인을 거쳐 기존 슬롯을 교체할 수 있다. | 종·폼, 특성, 도구, 성격, 배분과 기술 네 칸을 저장한다. 현재 HP·날씨·탈 소모는 전투 조건으로 다룬다. 완성 HTML에서 양측 저장, 기존 슬롯 교체 취소와 적용을 실행했다. |
| 데이터 생성 | 실제 빌드와 번역 갱신의 대상 ID를 통일했다. 동일한 PokéAPI 커밋의 이름·설명 7종을 검증하고 한 파일로 교체한다. 수동 번역이 우선한다. | 마이티폼을 포함한 대상, 마지막 CSV 요청 실패 후 기존 파일의 바이트 보존, 신규 캐시 파일의 변경 감지를 검증했다. 실제 외부 번역 데이터 갱신은 수행하지 않았다. |
| 동기화와 빌드 | 동기화 요약에서 변경 없음, 검증 중단, 커밋·푸시 실패, 성공, 번역 갱신 경고를 구분한다. 초기 용량은 HTML이 참조하는 자산과 정적 import를 따라 중복 없이 집계한다. | 워크플로의 실제 셸 분기에 모의 결과를 넣어 확인했다. 역계산 Worker와 4개 지연 메뉴를 초기 집계에서 제외하고 공통 청크를 포함하는 회귀 검사를 추가했다. |

## 샘플 구축 판정

| 대면 또는 용도 | 검증된 결과 |
|---|---|
| 고집 AS 스카프 몰드류 아이언헤드 → 명랑 AS 따라큐 | 일반 피해 범위는 186–222 HP다. 양측 만피에서 틀깨기는 온전한 탈에 확정 1타, 모래헤치기는 확정 2타다. 모래헤치기로 첫 공격 직후 따라큐는 114 HP가 남았다. 탈이 이미 깨졌다는 조건을 켜면 확정 1타다. |
| 한카리아스 땅고르기 → 천정부지 메가저리더프 | 일반 피해 102–122 HP와 천정부지 배지를 표시한다. 실제 공격 후에는 160 HP 그대로이고 KO 표시는 ‘무효’다. 같은 기술에 중력을 켜면 38–58 HP가 남아 확정 2타다. 틀깨기 몰드류의 땅고르기는 34–56 HP가 남아 확정 2타다. 일반 저리더프의 부유와 타오르는불꽃도 비교 사례로 검사했다. |
| 파티 상성표 | 해당 방어 슬롯의 기본 땅 상성은 0배다. 상성표의 방어 열은 특정 공격자와 필드를 선택해 치르는 한 대면을 계산하는 화면과 용도가 다르다. |
| 형태 역계산 | 관측한 잔여 HP를 실제 피해 경로와 맞춘다. 천정부지의 무효로 만피가 남은 관측과 강제 접지로 HP가 줄어야 하는 관측을 구분한다. 탈·흡수·회복도 잔여 HP에 영향을 준다. |
| 계산 범위 | 한 번 명중한 기술 사용을 1타로 센다. 연속기 안에서 탈이 소모되는 것과 기술을 한 번 더 쓰는 것을 구분한다. 천정부지로 상대를 쓰러뜨린 뒤 **다음 상대**에게 적용할 랭크, 임의 교체와 상대의 행동 선택은 후속 전투 상태가 필요한 별도 범위다. |

## 개선 우선순위

1. **게시 전 실제 브라우저 동작을 확인한다.** 현재 공개 방식인 Pages와 단독 HTML에서 320/375px·데스크톱, 슬롯 저장 후 포커스, 두 탭에서 같은 슬롯과 다른 슬롯을 동시에 편집하는 경우, 역계산 Worker 로드, 파티 이미지·파일 내보내기를 확인한다. 실제 결과가 있어야 버튼 배치나 간격을 바꿀 이유를 판단할 수 있다.
2. **역할이 겹친 모듈은 변경 지점부터 분리한다.** 파티 저장 코드에서 전체 UI로 향하던 정적 의존을 제거해 최대 순환 그룹이 19개에서 18개 모듈로 줄었다. 전체 `src`의 JS 50개와 정적 연결 275개 중 가장 큰 그룹에는 계산 상태·렌더·초기화와 파티 도구가 여전히 함께 있다. 다음에 입력·적용 경로를 바꿀 때 상태 변경과 화면 갱신을 한 방향으로 연결하고, 각 단계에서 계산기↔세부조정·파티 왕복 회귀를 실행하는 것이 적절하다. 1,854줄인 대미지 엔진은 효과군을 수정할 때 기존 난수·KO 대조를 기준으로 작은 단위로 나눌 수 있다.
3. **첫 화면 성능은 실측 후 판단한다.** Pages 초기 자산 5개의 gzip 합계는 263,122바이트, 전체 자산은 379,342바이트다. 초기 게임 데이터가 154,594바이트로 약 59%다. HTML·응답 헤더·스프라이트와 CDN 압축 차이는 이 수치에 포함되지 않는다. 모바일에서 첫 계산 결과까지 걸리는 시간과 첫 역계산 응답을 따로 측정한 뒤, 초기 데이터 분리가 필요한지 판단한다.
4. **다음 실제 데이터 변경에서 외부 연동을 확인한다.** 고정 샘플에서 중단과 복구를 검증했다. 운영 연결 시 첫 성공한 번역 스냅샷의 대상·누락 수, 수동 보정 유지 여부와 동기화 요약을 확인한다. 이 작업과 광고 레일 전환 일정은 독립적이다.

## 재현 명령

```sh
npm ci
npm test
npm run damage:reference -- --showdown /path/to/built/pokemon-showdown
npm run ui:audit
```

참조 대조에는 위에 기록한 SHA를 체크아웃해 빌드한 Showdown 사본이 필요하다. 단독 HTML은 오프라인으로 열 수 있다. Pages용 정적 파일은 HTTP로 제공한다. 수정은 로컬 작업 사본과 전달용 후보본에만 포함했다.
