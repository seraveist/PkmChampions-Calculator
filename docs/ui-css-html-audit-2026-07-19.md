# UI/CSS/HTML 전수조사 및 개편 가능성 보고서

- 조사일: 2026-07-19
- 대상 브랜치: `codex-ui-foundation-rebuild-20260719`
- 범위: HTML 구조, CSS 계층/소유권/반응형, UI JavaScript 경계, 공개·오프라인 빌드, 접근성
- 제외 범위: 대미지 계산 예외 및 계산 규칙 변경. 계산 엔진은 현행 동작을 유지했다.

## 결론

전면 또는 페이지 단위 UI 개편은 가능하다. 공통 토큰, 셸, 패널, 필드, 버튼, 콤보박스, 파티 프리셋, 능력치/기술 편집기가 분리되었고 페이지 CSS의 교차 소유권도 제거됐다. 따라서 공통 디자인 변경과 개별 페이지 레이아웃 변경을 이전보다 좁은 범위에서 진행할 수 있다.

현재 가장 큰 제약은 프레임워크가 아니라 문자열 템플릿과 전역 함수로 구성된 렌더링 방식이다. 시각 개편 자체를 막지는 않지만, DOM 구조를 크게 바꿀 때는 렌더 함수와 이벤트 위임 계약을 함께 수정해야 한다. 계산 엔진은 유일한 40 KiB 초과 JavaScript 파일로 남겼으며, UI 정리가 끝난 뒤 계산 예외를 별도 단계로 처리하는 것이 적절하다.

## 적용 결과

1. 모바일 세부조정/역계산 능력치 표를 가로 스크롤 없는 카드형 레이아웃으로 변경했다.
2. 공개 빌드에서 도감, 상성표, 세부조정, 역계산 기능을 페이지 진입 시 지연 로딩하도록 분리했다.
3. 포켓몬 쇼다운 원본 동기화 메타데이터에 26개 파일별 SHA-256을 추가하고 로컬 데이터 검증을 강화했다.
4. 공통 CSS에서 파티 프리셋과 도구 능력치/기술 편집기 스타일을 독립 컴포넌트 파일로 분리했다.
5. 계산기 콤보박스, 도감 상세, 세부조정 렌더링, 역계산 액션 코드를 작은 UI 모듈로 분리했다.
6. 상성표·세부조정·역계산 페이지 CSS에서 다른 페이지 선택자를 제거했다.
7. 320px 다크 모드, 전 페이지 접근성, 모바일 넘침, 공개 기능 지연 로딩, 역계산 Worker 응답성 검사를 추가했다.
8. HTML/CSS/JavaScript 구조를 반복 측정할 수 있는 `npm run ui:audit` 명령을 추가했다.

## 남은 개선 권장 순서

1. 새 시각 방향을 토큰과 공통 컴포넌트에 먼저 반영한다.
2. 셸/헤더를 개편한 뒤 계산기, 세부조정·역계산, 상성표, 도감 순으로 페이지를 개편한다.
3. 개편 과정에서 계산기·도감 CSS를 섹션 단위로 더 나누고, 계산기 CSS에 집중된 `!important`를 줄인다.
4. 44개 미디어 쿼리를 공통 breakpoint 기준으로 정리하되 페이지별 동작 검사를 유지한다.
5. 큰 DOM 구조 변경이 필요할 때만 문자열 렌더링을 작은 렌더 헬퍼 또는 컴포넌트 단위로 점진 전환한다.
6. UI/CSS가 확정된 뒤 `02-engine.js`와 계산 예외 목록을 별도 브랜치/커밋 단위로 처리한다.
