# 세부조정·상성표·도감 폰트 검토

2026-09-13. 소스 선언과 Chromium의 실제 computed style을 계산기와 대조했다. 글꼴 가족은 공통 본문에서 정상 상속하고 있었지만 크기·굵기에는 아래 차이가 있었다.

| 대상 | 확인한 문제 | 수정 결과 |
| --- | --- | --- |
| 세부조정 비교 값 | 일반 능력치 11px, 내구·속도 지표는 별도 override로 10px | 값 13px/650, 이름 12px, 증감 11px. 값은 두 열을 사용해 작은 화면에서도 표시 |
| 세부조정 스피드 표 | 헤더 500, 행 제목은 `th` 안의 `b` 때문에 실제 900 | 공통 헤더·행 제목 650, 불필요한 `b` 제거 |
| 상성표 포켓몬 이름 | 부모 750과 `strong`이 중첩돼 실제 900 | 800 명시 상속, 이름 줄 높이 1.35 |
| 상성표 폼·특성·기술 | 선택 값과 기술명이 다른 입력보다 작거나 얇음 | 폼·특성 13px/650, 기술 14px(모바일 13px)/650 |
| 도감 표·종족값 | 본문 12px로 다른 표의 13px와 다름 | 본문 13px, 헤더 11px/650 |
| 도감 상세 이름 | 계산기 이름은 800/1.35, 상세 이름은 700/1.5 | 이름 굵기 800, 줄 높이 1.35 |

세 메뉴의 데이터 표에 `ui-data-table`을 적용하고 공통 표의 크기·굵기를 `components/primitives.css`로 모았다. 메뉴 파일에 남아 있던 표 기본 폰트 선언을 제거했다. 세 메뉴의 글자 크기는 `tokens/rotom.css`의 역할별 토큰을 사용한다.

설명 문단의 여유 있는 1.8 줄 높이, 타입 배지와 슬롯 번호의 작은 표기, 선택 목록의 확정된 글자 위계는 역할에 맞는 차이로 유지했다. 계산기 화면의 표시값은 비교 기준이며 이번 수정으로 바뀌지 않았다.

검증: 세부조정·상성표·도감 전용 브라우저 검사 통과, HTML 구조·CSS 구조·중복 소유권 검사 통과, 세부조정 상태 및 도감 기능 검사 통과. 도감의 헤더/이름 열 스크롤과 실제 touch 이벤트 드래그도 통과했다. 320/390/1440px의 글자 표시와 작은 화면 팝업을 직접 확인했다.

실제 표시값은 `ui-font-review-before.json`, `ui-font-review-after.json`에 보관했다. 원시 표본의 `missing`은 해당 화면 상태에 없는 선택자를 뜻한다. 기기 범위는 Windows Chromium 및 반응형 에뮬레이션이다.
