# UI 리모델링 최종 검토

검토일: 2026-09-13. 확정된 계산기 샘플을 기준으로 본편의 다섯 메뉴와 파티·공통 팝업을 개편했다. 스마트 로토무 색상과 라이트·다크 테마, 간결한 표시를 유지했다.

## 메뉴별 마감

| 메뉴 | 최종 구성 | 기능·화면 검증 |
| --- | --- | --- |
| 대미지 계산기 | 공통 포켓몬·속성·능력치 입력, 상시 노력치/랭크, 접이식 필드, 중앙 교대, 통일된 피해/KO 결과 | 계산 조건·다타·급소·수동 타입, 결과 갱신, 메뉴 전달, 좁은 화면 |

각 메뉴의 구현과 전용 화면 검사 후, 공통 부품을 다시 대조하고 전체 검사를 수행했다. 본편 통합 이후에도 확정 샘플의 전용 브라우저 검사 238개가 통과했다.

## 공통 HTML·CSS 계층

- 포켓몬 선택, 도구·특성·성격 선택, 숫자·랭크 입력, 화살표, 검색창, 버튼, 제목과 팝업이 같은 공통 렌더러·CSS를 사용한다.
- 능력치 표는 같은 6열 구조다. 글자·입력 크기는 공통 토큰과 명시적 변형으로 관리한다.
- 포켓몬 목록은 이름·타입·종족값 열을 고정했다. 기술 목록은 타입 배지 → 굵은 위력 → 분류 → 설명, 성격 목록은 상승·하락 열을 공유한다.
- 검색 선택창을 하나의 native dialog 구현으로 통합했다. Enter·방향키·Escape·IME·포커스 복귀를 공유하며 선택 행 높이와 스크롤도 같은 규칙을 적용한다.
- 메뉴별 파일은 배치를 담당한다. 공통 외형을 메뉴 파일에서 재정의하던 규칙과 뒤에서 덮어쓰던 스타일 파일을 제거했다.
- CSS 소스는 18개 파일, 81,079바이트다. `!important`는 native `[hidden]`을 지키는 한 곳만 남았다.

정적 검사 결과: 중복 ID 0, 타입이 없는 버튼 0, 템플릿 인라인 스타일·이벤트 0. 같은 선택자/속성의 무조건부 중복 소유자, 뒤쪽 기본 규칙에 가려지는 반응형 선언, 메뉴 간 CSS 소유권 충돌도 각각 0이다. 세부 기준은 [CSS 구조](CSS-ARCHITECTURE.md)와 [반응형 정책](ui-breakpoints.md)에 기록했다.

## 최종 검증

- `npm test` 통과: 소스·HTML·CSS·JS 구조, 공개 산출물, 데이터, 피해·KO·역계산 및 각 메뉴의 상태 회귀 검사. 로그의 `[PASS]` 항목 995개, 실패 0개.
- 전용 실제 브라우저 검사 통과: 계산기 25, 세부조정 28, 역계산 25, 도감 127, 상성표 42, 파티 26개 항목. 도감은 아래 후속 검사를 포함한 수치다.
- 공통 최종 검사: 5개 메뉴 × 라이트/다크 × 9개 폭(320/375/390/700/768/900/901/1000/1440px), 총 90개 화면 조합과 5종 선택창.
- 위 조합의 문서 가로 넘침, 중복 ID, 깨진 HTML 참조, 중첩 인터랙션 요소는 0이다. 공통 능력치 입력의 실제 높이·모서리·정렬도 일치했다.
- 메뉴·선택창의 axe 검사에서 moderate/serious/critical 위반 0. 첫 진입 지연 로딩과 계산기→세부조정/역계산 전달, 수동 타입 초기화, 키보드 선택·IME·포커스 복귀를 확인했다.
- 검사 중 보고된 애플리케이션 실행 예외는 0이다. 이미지 CDN 등 외부 리소스 통신 오류는 이 집계에서 제외한다.

검증은 Windows의 Chromium 계열 실제 브라우저와 반응형 에뮬레이션 기준이다. iOS Safari·Android 실기기 검증 결과를 뜻하지 않는다. 모든 가능한 데이터·상태 조합이 무결함이라는 보증도 아니다.

## 도감 표·메뉴 탭 후속 수정

사용자 제보로 이전 검토가 놓친 잘못된 부품 클래스 연결을 확인했다. 도감의 네 표와 스크롤 컨테이너에 필터 버튼 클래스가 붙어 있어 이중 여백과 표 전체 hover 배경이 생겼다. 기존 정적 CSS 중복 검사는 이 HTML 클래스 오용을 검출하지 못했다.

- 브라우저에서 초기 이름 열이 컨테이너 안쪽 경계보다 24px 안에 배치되고, 스크롤 시작 후 12px 이동하는 현상을 재현했다. 헤더에도 세로 여백 이동이 있었다.
- 잘못된 버튼 클래스를 제거하고 표의 헤더·본문 배경과 행 높이를 정리했다. 헤더 셀과 이름 셀을 직접 고정하며 왼쪽 위 교차 셀의 쌓임 순서를 명시했다. 이름 열은 가로 넘침이 생기는 중간 화면 폭에서도 고정한다.
- 네 종류 표 × 네 화면 폭 × 두 테마에서 시작·중간·끝의 가로/세로 위치를 확인했다. 실제 touch 이벤트로 드래그하는 동안에도 헤더와 이름 열이 컨테이너 경계에 유지됐다.
- 메뉴 탭은 샘플처럼 모바일 동일 폭과 좌우 10px 여백, 중간 폭 20px 여백을 사용한다. 탭의 표기도 샘플과 같은 ‘역계산’으로 줄였다.
- HTML 구조 검사에 버튼 클래스가 표·일반 컨테이너에 붙지 않는지 검사하는 항목을 추가했다. 도감 기능·상태, CSS 구조·중복 검사 및 전 메뉴 최종 화면 검사를 다시 통과했다.

## 재검사 경로

세부조정·상성표·도감의 실제 폰트 크기·굵기 상속은 [후속 폰트 검토](ui-font-review.md)에서 추가 정리했다.

역계산 결과의 간결한 후보·노력치 예시, 상태 변화 및 기술 행 구성은 [역계산 결과 후속 검토](reverse-results-ui-review.md)에 기록했다. 후속 변경은 해당 문서의 범위로 재검증했다.

```powershell
npm test
npm run ui:browser -- --require-browser
npm run ui:browser:public -- --require-browser
npm run ui:browser:pages -- --require-browser
npm run calculator:browser
npm run finetune:browser
npm run reverse:browser
npm run dex:browser
npm run matchup:browser
npm run party:browser
npm run sample:calculator:browser
```

전체 브라우저 검사와 CI는 새 공통 UI 검사기로 연결했다. 원시 결과는 `ui-remodel-final-static.json`, `ui-remodel-final-browser.json` 및 메뉴별 `*-browser-verification.json`에 보관한다.
