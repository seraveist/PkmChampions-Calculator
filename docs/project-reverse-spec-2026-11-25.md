## 3. 제품의 목적과 다섯 메뉴

**주 사용자는 대전 전에 샘플을 만드는 사람이다.** 한 배치가 특정 상대를 몇 번의 기술 사용으로 쓰러뜨리는지, 속도·HP 목표를 채우면서 포인트를 얼마나 옮길 수 있는지, 같은 파티에 약점과 공격 타입이 어떻게 겹치는지를 확인한다. 이미 치른 대전의 잔여 HP와 행동 순서를 입력해 상대 배치를 좁히는 작업도 지원한다.

| 메뉴 | 사용자가 입력하는 것 | 계산 및 결과 | 판단 범위 |
|---|---|---|---|
| 대미지 계산기 | 양쪽 종/폼, 배분·성격·특성·도구, 기술 슬롯, 시작 HP와 상태, 등장 특성·날씨·필드·벽·대전 형식, 기술별 조건 | 결정력, 일반 피해 HP/비율, 실제 KO 타수·확률, 적용 특성과 조건을 기술별로 비교 | 명중한 기술 1회 사용이 1타다. 반복 시 상대의 임의 행동·교체는 가정하지 않는다. 연속기 내부 타격과 여러 번의 기술 사용을 구분한다. |
| 형태 역계산 | 내 배치, 상대 종/폼, 한 공방의 기술·선후공, 시작 HP와 관측 잔여 HP, 관측 시점, 알려진 특성·도구 | 관측과 양립하는 대표 배분과 범위, 다음 턴의 상태·선후공·피해 예측, 대표 배분을 계산기에 적용 | 싱글 관측 기준이다. 대표 후보의 순서는 실전 채용률이나 정답 확률을 뜻하지 않는다. 후보별 범위를 독립적으로 조합할 수 없다. |
| 세부조정 | 내 배치와 상대, 날씨·필드·상태·랭크·순풍, 목표 속도/차이, 남은 포인트 | 상대 속도 기준별 최소 S, 가능/부족/도달 불가, HP 조정에 따른 회복·소모 기준점, 양쪽 계산기 적용 | 한 능력 최대 32, 합계 66포인트. 부족할 때 다른 능력치에서 자동 차감하지 않는다. 현재 화면에는 과거 기준 배분 복원 기능이 없다. |
| 상성표 | 1~6마리, 폼·특성, 슬롯별 공격 기술, 타점 계산용 날씨·필드 | 18타입 방어 배율과 약점·반감·무효 마릿수, 각 공격 타입을 가진 마릿수 | 방어는 정적 타입·특성 기준이다. 상대 틀깨기·중력·도구·HP 등 대면 조건은 계산기에서 확인한다. 타점은 기술 타입 변환을 반영하고 동일 타입을 한 마리당 한 번 센다. |
| 도감 | 포켓몬/기술/특성/도구 탭, 한국어·영문 검색, 유형별 필터, 상세 선택 | 수록 종·폼·종족값·특성·학습 기술·상세 효과를 조회하고 계산기로 옮긴다. | 로컬 데이터셋의 수록·학습 정보를 제공한다. 모든 공식 대회에서 사용할 수 있는 조합이라는 인증 기능은 없다. |

**공통 파티**는 10파티 × 6슬롯이다. 각 슬롯은 종/폼, 특성, 도구, 성격, 6능력 포인트, 기술 4칸을 보관한다. 편집 결과는 브라우저의 `localStorage`에 저장한다. JSON은 전체 파티 백업, Showdown 텍스트는 특정 파티 교환, 이미지는 공유용 출력이다. 전체 가져오기나 특정 파티 텍스트 교체에는 확인과 직전 가져오기 1회 되돌리기가 있다. 이력은 일반 편집의 버전 관리와는 별개다. 테마 역시 로컬에 저장한다.

### 대미지 수치의 의미

| 표시 | 사용자가 답하려는 질문 | 고정할 제품 판정 |
|---|---|---|
| 결정력 | 이 샘플의 공격 기술 자체는 얼마나 강한가? | 공격 측 조건 중심의 비교값을 제시한다. 고정 피해·조건 미입력 기술은 정해진 표시를 따른다. |
| 기술 카드의 일반 피해 | 무효·차단 조건이 해제되면 이 상대에게 얼마가 들어가는가? | 별도 특성 무효·생존은 배지와 일반 피해 근거를 함께 보여 준다. 타입 자체의 무효와 명시적인 해제 규칙은 반영한다. |
| KO 타수 | 지금 설정한 상태에서 같은 기술로 쓰러뜨리는 데 몇 회 필요한가? | 지원하는 기술 사용·타격·턴 종료 상태를 반영한다. 확정·난수·행동 조건을 구분한다. 명중률·무작위 급소까지 섞은 승률로 해석하지 않는다. |
| 관측 역계산 | 실제 남은 HP가 이 배치에서 가능한가? | 공격 직후 또는 턴 종료라는 관측 시점에 맞춰 실제 HP 경로를 사용한다. 카드의 일반 피해를 관측치에 대입하지 않는다. |

제품 수용 예시로 고집 AS 스카프 몰드류의 아이언헤드가 명랑 AS 따라큐에게 주는 일반 피해는 로컬 기준 **186–222 HP**다. 틀깨기는 확정 1타, 모래헤치기와 온전한 탈은 확정 2타, 모래헤치기와 이미 깨진 탈은 확정 1타다. 메가저리더프의 천정부지는 기본 방어 상성표에서 땅 0배이고, 실제 관측에서는 중력이나 공격자 틀깨기에 따라 땅 기술로 HP가 줄 수 있다. 상대를 쓰러뜨린 후 상승한 능력치를 다음 대면으로 이어가는 효과, 교체 후의 상대 AI, 임의의 다턴 행동 선택은 이 제품의 계산 목표에서 제외한다.

## 6. 발견 사항과 완료 조건

### 6.1 자동 날씨·필드가 수동 설정으로 바뀐다

**재현.** 계산기에서 패리퍼의 잔비, 파도타기, 상대 잠만보를 선택한다. 바로 날카로운눈으로 바꾸면 날씨는 ‘없음’, 일반 피해는 46–55 HP다. 잔비 상태에서 세부조정에 들어가 아무것도 바꾸지 않고 ‘공격측 적용’ 후 날카로운눈으로 바꾸면 비가 유지되고 69–82 HP가 된다. 동일한 단독 HTML의 화면 조작으로 확인했다. 실제 상태 함수에서도 사이코메이커를 제거할 때 직접 경로는 필드가 사라지고, 왕복 경로는 사이코필드가 남았다.

**원인과 조치.** `src/js/04-31-finetune-render.js:107`은 반환할 때 날씨·필드를 모두 `setManualCalcField`에 전달한다. `src/js/03-40-calc-entry-effects.js:116`은 이 호출에서 설정 주체를 비우고 값을 수동 기준으로 저장한다. 세부조정 진입 시 자동 설정 주체와 기존 수동 기준을 함께 기록하고, 사용자가 해당 항목을 직접 편집했을 때만 수동 설정으로 전환한다. 양측을 바꿔 적용하면 주체도 새 측으로 매핑한다.

**완료 조건.** 동일 방향·공수 반전, 날씨·필드 각각, 사용자 수동 변경 유무, 양쪽 모두 등장 특성 보유, 자동 적용 끄기/켜기를 조합한다. 같은 입력의 직접 경로와 왕복 경로에서 특성 제거 후 필드·피해가 일치하고, 사용자가 명시한 수동값은 유지되어야 한다.

### 6.2 서로 다른 파티를 편집해도 앞선 저장이 사라진다

**재현.** 동일 출처의 공유 저장소와 저장 이벤트를 제공한 두 DOM 창에서 앱을 먼저 열었다. A 탭에서 1번 파티명을 ‘A-샘플’로 바꾸고 저장된 값을 확인했다. B 탭에서 2번 파티명을 ‘B-샘플’로 바꾸자 영속 저장값은 ‘파티 1 / B-샘플’이 됐다. 이름만 바꿔 재현했으며, 저장 단위가 전체 파티이므로 오래된 탭에서 다른 슬롯을 편집하는 경우도 보호 대상이다.

**원인과 조치.** `src/js/04-00-party-presets-state.js:58`에서 탭 시작 시 전체 파티를 읽고, `:284`의 저장 함수가 메모리 전체를 한 번에 쓴다. 한 번의 쓰기는 파티와 되돌리기를 함께 보존하지만 별도 탭의 최신 변경을 합치지 않는다. 편집 부위를 파티·슬롯 단위로 식별하고, 저장 시 최신 값과 비교해 다른 부위 변경을 병합한다. 같은 부위 충돌 및 JSON 전체 복원에는 새 버전 확인이 필요하다. 탭 간 쓰기가 겹칠 때를 포함해 직렬화할 수 있는지 확인하고, 불가한 환경에서는 오래된 저장을 감지해 사용자 편집을 보존한다.

**완료 조건.** 두 탭에서 서로 다른 파티와 같은 파티의 서로 다른 슬롯을 편집한 뒤 새로 열어 둘 다 남아야 한다. 같은 슬롯에 겹친 변경은 덮어쓰기 전 기존 팝업에서 확인한다. v1 JSON, 가져오기 되돌리기, 저장 금지·용량 초과 시 내보내기 경로도 함께 통과해야 한다.

### 6.3 광고 레일 유무와 게시 전환 기준

| 향후 전환 후보 | `npm run build:public` · `public` | `npm run public:ready`로 광고 레일 마크업을 확인한다. 실제 광고 노출은 연결 후 확인한다. |

### 6.4 Showdown 텍스트 일부만 읽혀도 누락 필드가 보이지 않는다

**재현.** 몰드류, 틀깨기, 스카프, 고집, 아이언헤드와 이름에 오타가 있는 기술 하나를 넣고, 다음 블록에 인식할 수 없는 종을 넣었다. 확인창은 ‘1마리로 교체’라고 안내했고, 승인 후 아이언헤드 한 칸만 채운 몰드류가 저장됐다. 어느 포켓몬과 기술이 빠졌는지는 확인창에 없었다. 전부 인식되지 않는 입력은 기존 경로에서 거절한다.

**조치와 완료 조건.** 파서 결과에 원래 블록·줄, 미인식 이름, 정규화된 포인트, 적용 대상 슬롯을 포함한다. 기존 확인창에 누락 목록을 표시하고 사용자가 취소하거나 일부 적용을 선택하게 한다. 챔피언스 포인트 한도를 넘는 일반 Showdown 입력도 조용히 잘라 쓰지 않도록 적용값을 보여 준다. 정상 포맷의 왕복은 그대로여야 하고, 경고 후 취소하면 기존 파티가 유지돼야 한다. 근거는 `src/js/04-02-party-presets-integration.js:149`, `:200`, `:256`이다.

### 6.6 초기 화면의 자산 크기가 실제보다 작게 집계된다

`npm run ui:audit`는 Pages 초기 자산을 gzip **172,779바이트**로 보고했다. 실제 앱 진입 파일은 공통 청크를 정적으로 import하고, 그 청크가 데이터를 import한다. 중복 제거 후 같은 기준으로 합하면 **259,836바이트**다. 차이 **87,057바이트**가 공통 청크 하나의 크기와 일치한다. HTML·응답 헤더·외부 이미지, CDN의 실제 압축률과 네트워크 속도는 이 비교에 포함하지 않았다.

`scripts/ui-architecture-audit.mjs:92`는 역할 이름 네 개만 더한다. 생성된 HTML 진입점에서 정적 import를 재귀적으로 따라가고 동적 메뉴 4개와 역계산 Worker는 각 기능의 비용으로 남겨야 한다. 초기·지연·전체 지표를 같은 manifest에서 검증하면 구조를 유지한 채 성능 회귀를 발견할 수 있다.

### 6.7 구조는 상태 전달과 검증 경계부터 정리한다

현행 ESM의 명시적 import, 메뉴 지연 로드, 공개/단독 공통 데이터 생산, 슬롯별 계산 무효화, 외부 Showdown 고정 리비전 비교는 유지할 가치가 있다. HTML 정적 검사에서는 다섯 페이지의 정적 ID 중복, 타입 없는 버튼, 인라인 이벤트가 각각 0개였다. 수치나 파일 길이만으로 전체 화면이나 엔진을 교체할 근거는 부족하다.

반면 JS 50개에서 정적 모듈 의존 간선 275개가 확인됐다. 상호 도달하는 최대 그룹은 19개 파일로, 공통 HTML·초기화, 계산 상태·렌더·이벤트, 파티 저장·이미지·UI가 한 그룹이다. 역계산 핵심 5개, 역계산 UI 3개, 세부조정 3개, 도감 2개도 각각 순환 그룹이다. 이는 실행 오류 건수가 아니다. 저장이나 상태 전달을 수정할 때 렌더·초기화까지 고려해야 하는 구조적 이유다.

1. 먼저 **샘플 배치**, **대전 시작 상태**, **공통 필드와 자동 설정의 출처**, **관측 입력**, **계산 결과**의 소유 모듈과 전달 필드를 정의한다. 복사·초기화 규칙은 메뉴별 이벤트 핸들러에서 분리한다. 세부조정 왕복 회귀를 먼저 고정한다.
2. 파티의 읽기·검증·저장 함수를 DOM 갱신과 분리한다. 성공·충돌·영속 저장 실패 결과를 UI가 받아 기존 경고 영역에 표시한다. 데이터 형식 호환을 유지한다.
3. 도감·선택창·파티가 공유하는 UI는 현행 컴포넌트를 유지한다. VM 골든용 어댑터는 import 문법과 지연 로드를 바꾸므로, 메뉴 왕복과 Worker 검사는 계측하지 않은 실제 번들 경로도 계속 실행한다.
4. 계산 엔진은 새 책임이 식별되는 변경에서만 분리한다. 반올림·난수 분포·접지·특성 무시는 공통 규칙을 사용하고, 일반 피해·KO·관측의 목적 차이는 함수 입력과 회귀 사례로 명시한다.

소스 경계는 `src/main.js`, `src/runtime/features.js`, `src/js/03-10-calc-state.js`, `src/js/04-00-party-presets-state.js`, `scripts/source-utils.mjs:25`, `scripts/modules-golden.mjs`에서 확인할 수 있다.

## 7. 프론트엔드 변경 범위와 적용 순서

다섯 메뉴의 순서, 기술 카드, 전역 파티 버튼을 유지한다. 날씨·필드 오류는 기존 화면에서 수정할 수 있다. 샘플 재입력을 줄이려면 계산기에서 완성한 배치를 파티에 저장하는 동작을 고려한다.

| 순서 | 구현 단위 | 화면 변경 | 완료 기준 |
|---|---|---|---|
| 1 | 자동 필드 출처 보존, 파티 동시 편집 보호 | 기존 필드 표시·파티 경고/확인 영역 재사용 | 동일 샘플의 피해 재현값 일치, 다른 탭의 비충돌 변경 보존, 이전 JSON 및 되돌리기 통과 |
| 2 | 결정력/KO·세부조정 문서 링크 정리 | 문서 수정 | README에서 실제 구현과 현행 판정 기준으로 연결한다. |
| 3 | Showdown 부분 가져오기 진단, 번역 캐시와 동기화 요약, 자산 집계 수정 | 가져오기 확인창에 원문 줄과 사유 표시 | 누락 내역 확인 후 취소/적용, 캐시 중간 실패 복구, 필수 청크 한 번만 집계 |
| 4 | 계산기 패널의 ‘불러오기’ 옆에 **‘파티에 저장’** 한 동작 추가 검토 | 기존 파티 선택창에서 파티와 슬롯을 선택한다. 좁은 폭은 기존 동작 메뉴를 활용한다. | 빈 슬롯 저장, 사용 중 슬롯 교체 확인, 취소 시 보존, 키보드 포커스 복귀. 재호출 시 폼·특성·도구·성격·포인트·기술 4칸이 일치한다. HP·날씨·탈 소모는 저장 대상에서 제외한다. |
| 5 | 외부 브라우저에서 최종 확인 | 기능 확인 후 필요한 경우에만 버튼 간격 조정 | Pages와 단독 HTML 각각에서 모바일 320/375px·데스크톱, 키보드, 다이얼로그 포커스, 실제 두 탭과 실제 Worker, 파티 이미지·파일 저장을 확인 |

4번은 신규 편의 기능이다. 1~2번의 수정과 독립적으로 결정할 수 있다. 운영 데이터베이스 추가, SPA 프레임워크 교체, 전투 시뮬레이터 전면 이식은 이번 발견 사항의 해결에 필요하지 않다.
