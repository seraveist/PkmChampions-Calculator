# 결정력 계산 메뉴 완성도 분석

후속 상태: 아래는 보완 전 진단이다. 확인된 우선순위 1·2 항목의 해결 내용과 위력 입력 재현의 정정은 [보완 결과](calculator-menu-improvements-completed.md)를 참고한다.

검토일: 2026-09-08. 대상: 현재 수정 작업 사본의 HTML·CSS·JS, 단독 실행 HTML, 배포용 화면. 이번 작업에서는 제품 코드를 수정하지 않고 진단 자료만 추가했다.

## 평가

**일반적인 피해 비교에는 실용성이 높지만, 특수 조건의 KO 판정과 화면 전달까지 포함하면 완성 판정을 내리기 어렵다.** 다음 단계는 기능 수를 늘리는 것보다, 결과의 정확성과 사용자가 그 결과를 제대로 해석할 수 있는지를 마무리하는 작업이다.

평가 목적은 사용자가 확정한 결정력 계산이다. 상대의 턴 행동, 공격자의 반동 후 생존, 명중 실패를 포함한 승률, 모든 턴의 자동 진행은 필수 기능으로 평가하지 않았다. 타입·특성 무효를 안내하면서 피해를 계산하는 정책도 감점 이유가 아니다.

| 평가 영역 | 판단 | 근거 |
| --- | --- | --- |
| 목적 적합성 | 높음 | 무효·생존을 안내와 분리하고 직접 피해 보정 및 생존 후 회복을 다룸 |
| 일반 피해 산출 | 높음, 검증된 범위에서 | 천진·화상·정수 HP·날씨·스피드·타격별 계산 등의 재현 검사 통과 |
| 회복·확정/난수 KO | 보완 필수 | 독립 난수 합산은 동작하지만 탁쳐서떨구기와 회복열매 처리 순서 오류로 필요 타수가 달라짐 |
| 조건 입력 완결성 | 보통 | HP·선후공·트릭룸·연속기 입력은 있으나 총대장·성묘의 쓰러진 아군 수가 화면에서 빠짐 |
| 기술 목록과 결과 일관성 | 보통 | 고정 피해의 결정력이 0, 기본 위력과 적용 위력 및 수동 고정 여부가 불명확 |
| 데스크톱 결과 가독성 | 보완 필요 | 카드의 고정 높이 때문에 무효와 회복 설명을 함께 표시하면 일부 잘림 |
| 모바일 판단 정보 | 보완 필수 | 카드 제목·회복 설명·KO 배지 겹침. 고정 요약에 KO 확률과 무효 조건이 빠짐 |
| 검증·유지보수 기반 | 양호 | 단계별 엔진, 상태 복제, 회귀 검사와 브라우저 검사가 존재. 입력 도달 가능성·가림·효과 순서의 검사는 더 필요 |

완성도 수치는 계산 정확도와 혼동될 수 있어 백분율로 환산하지 않았다. 분류표에 모든 ID가 있다고 모든 조합이 검증된 것은 아니고, 검사가 통과했다고 모든 화면 내용을 읽을 수 있는 것도 아니다.

## 우선순위 1: 실제 판단을 바꾸거나 가리는 문제

### 회복열매를 떨구기 전에 회복시킴

현재 `resolvePowerMoveUse()`는 `recoverPowerHit()`를 호출한 후 도구 제거를 처리한다. 자뭉열매 발동선을 넘기는 탁쳐서떨구기에 부당한 회복이 생긴다.

재현은 현재 수록 기술을 실제로 배우는 괴력몬을 사용했다. 양측 무투자·무보정 성격, 방어측 잠만보는 특성 없음, 최대 HP 235/현재 HP 150, 자뭉열매 조건이다.

| 항목 | 현재 | 제거를 회복보다 먼저 적용한 기준 |
| --- | --- | --- |
| 첫 공격 피해 | 65~77 | 65~77 |
| 첫 공격 뒤 HP | 131~143 | 73~85 |
| 차이 | 자뭉열매 58을 먼저 회복 | 열매를 제거했으므로 회복 없음 |
| 필요 사용 횟수 | 난수 4타 85.2%, 5타 이내 확정 | 확정 3타 |

기준의 근거는 Showdown에서 탁쳐서떨구기가 `AfterHit`에 도구를 제거하고, 자뭉열매의 `Update`는 그 뒤 실행되는 순서다. 이는 전투 전체를 재현하는 기능 확장이 아니라 이미 지원하는 회복 도구와 제거의 처리 순서를 맞추는 수정이다.

앱 근거: `src/js/02-engine.js:1403`와 `:1404`. 원본 근거: [기술의 도구 제거](https://github.com/smogon/pokemon-showdown/blob/master/data/moves.ts), [타격과 Update 실행 순서](https://github.com/smogon/pokemon-showdown/blob/master/sim/battle-actions.ts), [자뭉열매 Update](https://github.com/smogon/pokemon-showdown/blob/master/data/items.ts). KO 기준값은 현재 엔진의 피해 분포를 유지하고 이 회복 순서만 바로잡은 비교이며, 게임 실기 실측이라는 뜻은 아니다.

도구가 제거되어 회복하지 않는 경로에서도 `hkoLabel()`은 초기 도구를 보고 ‘자뭉열매 회복 반영’을 출력한다. 회복 설명도 실제 적용 경로와 연결할 필요가 있다.

### 카드가 중요한 내용을 가림

새로 1440px·375px·320px에서 일반 피해, 무효+회복, 연속기+회복을 각각 확인했다. 화면 갱신을 두 프레임 기다린 뒤 재측정해 동일하게 재현했다.

- **1440px:** 카드 높이 232px. 무효+회복 사례의 회복 설명은 카드 위쪽 기준 221.25~242.25px에 배치된다. 카드의 `overflow: hidden` 때문에 아래가 잘린다.
- **375px:** 회복 설명은 181.25~202.25px, KO 배지는 173~213px에 배치되어 겹친다.
- **320px:** 회복 설명은 194.75~215.75px, KO 배지는 173~213px로 역시 겹친다.
- **모바일 카드 제목:** 배정 높이는 6px인데 내부 내용 높이는 47px다. 기술명·타입 배지가 피해 영역과 겹치는 모습도 확인했다.

HTML에 설명을 추가했지만 CSS는 `top / range / info`의 기존 세 영역과 고정 높이를 유지한다. 새 설명은 이름이 지정되지 않은 추가 행에 배치된다. 카드가 내용에 따라 늘어나도록 하고, 제목·계산 조건·피해·KO를 명시적으로 배치해야 한다.

근거: `src/styles/pages/calculator-30-results.css:15`, `:24`, `src/styles/pages/calculator-00-base.css:486`, `src/styles/responsive.css:344`. 이번 재현 자료는 `docs/calculator-menu-browser-assessment.json`에 있다.

앞선 브라우저 85개 검사가 통과한 사실은 유지된다. 다만 그 검사에서 ‘표시됨’은 주로 요소 존재와 `display !== none`, 가로 넘침, 접근성 규칙을 확인한 것이다. **모든 설명의 잘림·겹침까지 검사했다는 의미로 확장할 수 없다.**

## 우선순위 2: 입력과 표시의 완결성

### 쓰러진 아군 수를 입력할 수 없음

`fallenAllies` 상태와 계산, 변경 이벤트는 있지만 실제 입력 요소를 렌더링하는 코드가 없다. 전체 공격측 패널을 생성해 확인해도 입력이 나오지 않는다.

| 실제 선택 가능한 사례 | 내부 값 0 | 내부 값 2 | 사용자 입력 |
| --- | --- | --- | --- |
| 대도각참·총대장·도각참 → 잠만보 | 위력 85, 피해 88~105 | 보정 위력 102, 피해 105~124 | 없음 |
| 대쓰여너·성묘 → 잠만보 | 위력 50, 피해 45~54 | 위력 150, 피해 132~156 | 없음 |

위력 직접 입력으로 일부 가정은 대신할 수 있으나 총대장의 모든 기술 공통 보정까지 명확하게 입력하는 기능과 같지는 않다. 관련 기술·특성을 선택했을 때 싱글 0~2, 더블 0~3 입력을 노출해야 한다.

근거: `src/js/03-10-calc-state.js:23`, `src/js/03-31-calc-conditions.js:2`, `src/js/03-30-calc-side-render.js:519`, `src/js/02-engine.js:457`, `:730`. 순풍 역시 엔진의 `side.tailwind` 분기는 있으나 계산기 입력 경로가 없다. 스피드 의존 위력까지 다루려면 입력 범위 점검에 포함할 만하다.

### ‘결정력’ 숫자의 의미가 특수 기술에서 깨짐

괴력몬 지구던지기는 결과 피해가 50~50인데 기술 목록의 결정력은 0이다. `estimateMovePower()`가 `fixedDamageKind`와 일격기만 고정 피해로 분류하고 `move.damage === 'level'`을 놓친다. 나이트헤드도 같은 데이터 형식이므로 영향을 받는다.

필요한 수정은 ‘고정 50’처럼 해당 기술의 의미를 전달하는 분류다. 일반 공격 지수에 0을 넣으면 기술이 피해를 못 주는 것으로 오해할 수 있다.

근거: `src/js/03-20-calc-combobox.js:23`.

### 기본 위력·적용 위력·수동 고정이 구분되지 않음

블레이범 HP 76/153의 분화는 정상적으로 적용 위력 74로 계산되지만 기술 목록의 위력 입력칸은 기본 위력 150을 보여준다. 기본 위력을 편집할 수 있는 것 자체는 문제없으나, 현재 적용 위력이 카드에 별도로 명시되지 않아 결과를 확인하기 어렵다.

같은 150을 직접 입력하면 가변 위력이 비활성화되어 적용 위력이 150으로 고정된다. 외형상 입력값은 같고 수동 고정 표시도 없다. 사용자는 자동 위력이 적용되는 상태와 직접 고정한 상태를 구분하기 어렵다.

자동/수동 상태, 실제 적용 위력, 자동 계산 복원 동작을 함께 노출할 필요가 있다. 근거: `src/js/03-10-calc-state.js:569`, `:583`, `src/js/03-30-calc-side-render.js:76`.

### 모바일 요약에 확률과 조건이 빠짐

모바일 요약은 기술명·피해 비율·확정/난수 타수만 출력한다. `hko.pct`와 무효·생존 제외 안내가 없다. 실제로 피카츄 10만볼트 → 한카리아스에서 결과 카드에는 땅 타입 무효 안내가 있지만 고정 요약에는 없다. 낮은 확률의 ‘난수 N타’도 확률 없이 보인다.

‘난수 2타 12.1%’와 ‘난수 2타 99.6%’를 구분할 확률은 요약에서도 핵심 정보다. 무효를 제외한 계산인 경우 최소한 ‘무효 조건 제외’ 표시를 함께 제공하는 것이 목적에 맞다.

근거: `src/js/03-50-calc-results.js:65`, `:71`.

### 계산 정책의 노출 위치

무효 제외·회복 반영·1타의 정의는 HTML에 설명되어 있다. 그러나 기본적으로 접혀 있는 ‘필드·부가 효과’ 내부에 있어 새 사용자에게 처음부터 보이지 않는다. 실제 적용 중인 날씨·필드·자동 진입 보정도 입력값과 파생값을 종합해서 읽어야 한다.

결과 바로 위의 짧은 계산 기준과 적용 조건 요약이 필요하다. 무효 계산의 상성 배지도 ‘1배/1/2배’만 보여주기보다 ‘계산상 배율’이라는 의미를 전달하는 편이 혼동을 줄인다.

근거: `src/calc-template.html:111`, `:156`, `src/styles/pages/calculator-10-layout.css:116`.

## 충분히 갖춰진 부분

- 공격·방어 포켓몬, 폼·타입·특성·도구·노력치·성격·랭크·HP 조건을 설정하고 최대 네 기술을 비교하는 기본 흐름.
- 순수 피해 범위와 최대 HP 대비 비율, 현재 HP 기준 KO 판단.
- 기합의띠·옹골참·탈과 타입·특성 무효를 안내로 분리하는 정책.
- 멀티스케일·반감열매 등 직접 보정과 일반 회복 도구의 반영.
- 독립 난수로 확정·난수 타수를 구분하는 구조, 연속기와 기술 사용 횟수의 분리.
- 정수 HP, 선후공·트릭룸, 트리플악셀 적중 횟수와 집단구타 참여자 입력.
- 파티 불러오기, 공수교대, 세부조정·역계산으로 이어지는 흐름.

노력치별 세팅을 여러 개 나란히 보존하거나 상대 내구 형태별로 동시에 비교하는 기능은 후속 편의 개선으로 볼 수 있다. 우선순위 1·2보다 먼저 추가할 필요는 없다.

## 확인 범위

- 이번에 기존 계산기 완료 검사 28개와 결정력 정책 검사 77개를 재실행하여 통과했다.
- 추가 함수·표시 진단 12개를 실행했다. 이 중 메가캥카+그로우펀치는 현재 배우는 기술에 없어 대상에서 제외했다. 12개 버그 또는 12개 독립 정답 검증이라는 의미는 아니다.
- 실제 피해 재현의 공격측 포켓몬·기술은 수록 데이터와 배우는 기술 목록을 확인했다. 과거 미수록 도구 입력을 오류 재현으로 오인했던 방식은 사용하지 않았다.
- 실제 브라우저에서 3개 화면 너비 × 3개 결과 조건을 측정하고 스크린샷을 확인했다.
- 타격 중 모든 특성 교환, 모든 회복 도구·기술 조합의 독립 정답 대조는 완료하지 않았다. 메가 집단구타의 반환 `bp` 정보와 실제 사용된 참여자 위력이 다른 사례도 진단에 남겼으며, 핵심 피해 오류로 확정하지 않았다.
