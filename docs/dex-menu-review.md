# 도감 메뉴 완성도 검토

> 아래는 수정 전 검토 기록이다. 보완 적용 결과와 현재 검증 방법은 [도감 개선](dex-improvements.md)을 참고한다.

검토일: 2026-09-13. 기준: `d05592c`와 로컬 세부조정 개선이 반영된 현재 프로젝트.

도감의 목적은 **기본 데이터 조회**다. 현재 검색·분류·상세·관련 항목 이동 구조를 유지하면서, 데이터 표시와 계산기 전달의 정확성을 보완하는 것이 적합하다. 이번 검토에서는 도감 제품 코드를 수정하지 않았다.

## 갖춰진 기능

- 포켓몬·기술·특성·도구의 네 분류, 한국어·영문 검색, 정렬, 페이지 이동, 탭별 검색/필터/페이지/스크롤 상태 보존.
- 포켓몬의 종족값·타입·무게·특성·다른 폼·타입별 학습 기술·방어 타입 상성.
- 기술의 분류·명중·우선도·연속 공격·설명·사용 포켓몬, 특성의 설명·보유 포켓몬.
- 도구의 설명·분류·전용 포켓몬·메가진화 대상과 계산기 적용.
- 포켓몬↔기술·특성, 도구↔메가진화 대상의 연결.

생성 데이터는 폼 포함 포켓몬 **350개**, 기술 **569개**, 특성 **317개**, 도구 **167개**다. 모두 한국어가 포함된 이름이 있고 기술·특성·도구의 짧은 설명이 비어 있지 않다. 이 검사는 데이터 존재 확인이며, 모든 번역의 정확성이나 현재 레귤레이션의 실시간 합법성을 인증하지 않는다.

## 보완 우선순위

### 1. 계산기 적용 시 새 기술에 이전 조건이 남음 — 우선 수정

기존 슬롯을 수동 위력 200, 불꽃 타입, 급소로 설정한 뒤 도감에서 지진을 적용하면, 기술 이름만 지진으로 바뀌고 계산용 기술은 **위력 200·불꽃·급소**로 남는다. 기존 연속기 적중 횟수도 보관되어 다음 연속기에 영향을 줄 수 있다.

다음 세 경로 모두 재현했다.

- 일반 기술 도감 → 슬롯 적용.
- 현재 공격측과 같은 포켓몬의 학습 기술 → 슬롯 적용.
- 기술의 사용 가능 포켓몬에서 현재 공격측과 같은 포켓몬 → 공격측 적용.

포켓몬 자체를 교체하는 경로에는 초기화가 있지만, 같은 포켓몬에서 기술을 교체하는 경로에는 없다. 계산기 내부에서 기술을 바꿀 때는 이미 해당 슬롯의 위력·타입·급소·적중 횟수를 초기화하므로, 도감 적용도 같은 규칙을 공유해야 한다. 다른 슬롯과 포켓몬의 노력치·성격·필드 조건은 유지한다.

근거: `src/js/04-11-dex-detail.js`의 `applyDexAction`, `src/js/03-30-calc-side-render.js`의 기술 선택 처리, `src/js/03-10-calc-state.js`의 `calcMoveWithConditions`.

### 2. 기술 PP가 전체 누락됨 — 필수 기본 정보

로컬 원본에는 569개 기술 모두 PP가 있지만, 빌드가 최종 기술 데이터에 PP를 내보내지 않는다. 따라서 기술 상세의 PP가 모두 `—`로 표시된다.

예: 10만볼트 원본 PP 15, 토치카·부리캐논 챔피언스 오버라이드 PP 5 → 모두 화면에서 `—`.

최종 병합된 챔피언스 데이터의 PP를 내보내야 한다. 다른 세대의 원본 값만 가져와 챔피언스 수정값을 덮어쓰지 않도록 검증한다.

근거: `build.mjs`의 `finalMoves`, `src/js/04-11-dex-detail.js`의 `renderMoveDetail`.

### 3. 조건 설명과 가변 위력 표시를 통일해야 함

| 항목 | 현재 표시 | 현재 프로젝트 계산에서 확인한 조건 |
|---|---|---|
| 솔라빔·솔라블레이드 | 쾌청 외 ×0.5 | 날씨 없음은 원래 위력. 솔라빔은 날씨 없음 120, 비 60 |
| 라이징볼트 | 일렉트릭필드 ×2 | 대상이 접지해야 증가. 비행 대상 70, 접지 대상 140 |
| 와이드포스·미스트버스트 | 필드 이름과 배율만 표시 | 사용자의 접지 조건이 있음 |
| 탁쳐서떨구기 | 도구 보유 시 ×1.5 | 해당 포켓몬의 메가스톤이면 원래 위력. 리자몽의 리자몽나이트X 65, 먹다남은음식 97 |
| 자이로볼·일렉트릭볼 | 목록 `가변`, 상세 `—` | 목록과 상세가 서로 다른 표시 함수를 사용 |
| 내던지기·집단구타 | 목록·상세 모두 `—` | 가변 위력 정보가 있으나 도감의 별도 설명표에 없음 |
| 변덕레이저 | 위력 80, 가변 안내 없음 | 엔진에는 80/160 조건을 구분하는 정보가 있음 |

기본 위력, 가변 위력, 고정 피해, 변화기를 구분하고 목록·상세·학습 기술 안내에 동일하게 적용한다. 위력 조건은 계산기의 메타데이터를 함께 사용하고, 설명에 필요한 접지·보유 도구 등의 전제는 짧게 명시한다. 새로운 공방 시뮬레이션은 필요하지 않다.

근거: `src/js/04-10-dex.js`의 `VARIABLE_BP_NOTE`, `movePowerLabel`, `src/js/04-11-dex-detail.js`의 `renderMoveDetail`, `src/js/02-engine.js`의 `computeVariableBp`.

### 4. 현재 수록 범위와 일반 참고 데이터를 구분해야 함

현재 350개 포켓몬의 학습 목록과 연결되지 않는 기술이 **60개**, 보유 포켓몬이 없는 특성이 **101개**다. 기술에는 원본 태그가 `Gmax`인 33개와 `LGPE`인 13개도 포함되어 있다. 현재 필터는 `Past`·`Future`·`CAP`·`Custom` 등을 제외하지만 이 태그들은 남긴다. 최종 출력에는 해당 출처 태그도 없다.

사용자가 현재 레귤레이션에서 사용할 수 있는 목록으로 오해하지 않도록, 현재 수록 포켓몬과 연결된 항목을 기본으로 보여 주고 일반 참고 항목을 구분하는 방식을 권장한다. 적어도 상세에서 ‘현재 수록 포켓몬 중 사용/보유 대상 없음’을 명시해야 한다.

**현재 사용자가 없다는 이유만으로 모두 삭제하거나 불법으로 판정해서는 안 된다.** 발버둥처럼 학습 목록에 없어도 의미가 있는 기술이 있다. 실제 사용 불가 항목의 제외는 레귤레이션 근거와 별도로 대조해야 한다.

### 5. 기본 정보에 맞는 표현으로 정리

- 특성의 `평가 5.0 / 5 — 필수급` 등은 Showdown의 일반 평가값을 가공한 것이다. 현재 M-C 환경의 사용률·추천도처럼 보이지 않도록 제거하거나 출처·평가 범위를 표시한다. 기본 도감에는 효과와 보유 포켓몬만으로 충분하다.
- 기술의 `플래그`, `미러 카피`, `메트로놈`, `하늘 미사용`, `Instruct 실패` 등은 내부 정보를 그대로 노출한다. 접촉·소리·펀치·베기·파동 등 판단에 유용한 특징과 자연스러운 한국어 설명 중심으로 정리한다. `authentic: 실체화` 같은 번역은 원본 효과와 대조해야 한다.
- 포켓몬의 `방어 타입 상성`은 타입만 계산한다. 현 제목상 타입표로서 틀린 결과는 아니며, ‘특성·도구 제외’라는 짧은 기준 안내를 추가하면 부유 등의 실제 방어 효과와 혼동을 줄일 수 있다.

## 검증과 마무리 기준

- 기존 `npm run dex:smoke` 통과: 기본 데이터 존재, 관련 데이터 연결, 폼 학습 기술, 화면 구성 검사.
- `node scripts/dex-menu-review.mjs`: 현재 앱의 실제 렌더링·적용·위력 처리 함수를 간단한 DOM 환경에서 실행해 위 문제를 재현. 계산기 `renderSide`도 실행하며 자동 재계산 예약만 생략했다.
- 재현 결과: [dex-menu-review-probes.json](dex-menu-review-probes.json).
- 이번 추가 검증에는 실제 브라우저의 전체 화면·접근성 재검사나 외부 최신 레귤레이션 전수 대조는 포함하지 않았다.

기존 검사는 위의 PP 누락·의미상 조건 오류·같은 포켓몬의 기술 적용 문제를 잡지 못한다. 보완할 때는 최종 챔피언스 PP, 대표 가변 위력 표시, 세 적용 경로의 상태 초기화, 현재 수록 범위 표기를 검증 항목으로 추가하면 된다. 마지막으로 실제 화면에서 검색→상세→관련 항목→계산기 적용과 모바일 읽기 흐름을 확인한다.

이 다섯 범주를 보완하면 도감은 요청한 기본 데이터 조회 역할로 마무리할 수 있다. 대전 형태 추천·승패 판정 등의 추가 분석 기능은 이번 도감 범위에 필요하지 않다.
