# 계산기 완료 및 다음 메뉴 착수 판단

후속 상태: 아래는 예외 기술 보완 전 재검토다. 지적한 세 항목은 반영 및 검증을 마쳤으며 [최종 보완 결과](calculator-special-moves-completed.md)에 따라 다음 메뉴 개선으로 전환할 수 있다.

검토일: 2026-09-08. 현재 수정 사본의 HTML·CSS·JS와 실제 수록 포켓몬의 기술 목록을 확인했다. 이번 검토에서는 제품 코드를 변경하지 않았다.

## 판단

**일반적인 결정력 계산의 사용성은 확보했지만, 계산기를 최종 완료 처리하고 다음 메뉴로 전환하는 것은 아래 예외 기술 처리를 마친 뒤가 적절하다.** 앞선 보완 요청에서 지적된 항목은 수정되어 있다. 이번에는 기존 회귀 검사가 다루지 않은, 선택 가능한 특수 기술의 계산 및 입력 경로를 추가 점검했다.

## 새로 확인한 항목

### 1. 변덕레이저의 강화 분기가 결과에서 빠짐

실제 수록 조합인 과미드라의 변덕레이저 → 잠만보, 무투자·무보정, 도구 없음, 자동 진입 효과 해제, 잠만보 현재 HP 100/최대 HP 235로 재현했다.

| 조건 | 피해 | 표시/계산 |
| --- | --- | --- |
| 현재 자동 계산 | 49~58 | 난수 2타 96.5%, 3타 이내 확정 |
| 강화 위력 160을 수동으로 분리한 비교 | 97~115 | 강화 조건에서 난수 1타 81.3% |

수록 설명과 원본 규칙에는 30% 강화 분기가 있다. 위 두 분포를 조합하면 이 사례의 1회 KO 가능성은 `0.3 × 13/16 = 24.375%`다. 현재 자동 결과 카드에는 일반 위력만 적용한 조건이라는 설명도, 강화 선택 입력도 없다. 이 확률은 현재 엔진의 두 피해 분포를 조합한 재현값이며 게임 실측을 의미하지 않는다.

최소 완료 조건: 일반/강화 조건을 명시적으로 선택·표시하거나 해당 분기를 피해 및 KO 분포에 반영해야 한다. 추가 행동이나 턴 전체 시뮬레이션이 필요한 사항은 아니다.

앱 근거: `src/js/02-engine.js`의 `computeVariableBp()` 기본 반환, `src/js/03-31-calc-conditions.js`의 조건 입력, `src/js/03-50-calc-results.js`의 결과 렌더링. [원본 기술 규칙](https://github.com/smogon/pokemon-showdown/blob/master/data/moves.ts#L5209).

### 2. 카운터류에 일반 위력 입력이 허용됨

카운터·미러코트·메탈버스트·앙갚음은 기본 상태에서 계산 불가지만, 위력에 100을 직접 입력하면 일반 공격식으로 피해와 KO를 산출한다. 실제 UI에서 사용하는 `applyMoveBpInput()` 경로로 확인했다.

| 실제 수록 조합 | 위력 100 수동 입력 후 출력 |
| --- | --- |
| 리자몽 카운터 → 잠만보 | 피해 92~110, 확정 3타 |
| 거북왕 미러코트 → 잠만보 | 피해 31~37, 난수 7타 |
| 깜까미 메탈버스트 → 잠만보 | 피해 43~51, 난수 5타 |
| 헬가 앙갚음 → 잠만보 | 피해 73~87, 난수 3타 |

이 기술들은 받은 피해량으로 결정되어야 한다. 일반 위력·공격·방어·상성 배율로 산출한 값은 해당 기술의 결정력으로 사용할 수 없다. 수동 표시가 있어도 기술 규칙 자체가 바뀌었다는 안내는 없다.

최소 완료 조건: 받은 피해량 입력을 지원하거나, 미지원 이유를 명시하고 일반 위력 입력을 막아야 한다. 반격 기술을 위해 상대 턴을 자동 시뮬레이션할 필요는 없다.

근거: `src/js/03-10-calc-state.js`의 `isFixedPowerMove()`·`applyMoveBpInput()`, `src/js/02-engine.js`의 `calculateBasePowerStage()`. 원본 규칙은 현재 빌드의 각 기술 `descLong`에도 포함되어 있다.

### 3. 내던지기·토해내기의 조건과 지원 범위가 불명확함

- 리자몽은 내던지기를 실제로 배운다. 수록 도구인 검은철구를 지녀도 자동 피해 계산은 `null`이며 ‘현재 조건에서는 피해를 계산할 수 없습니다’만 표시된다. 도구별 위력 연결이 없다.
- 아보크는 토해내기를 실제로 배운다. 비축 횟수 입력이 없고 기본 계산은 동일하게 `null`이다.

수동 위력으로 알려진 조건을 대신하는 것은 가능하나, 자동 계산 지원과 같지는 않다. 최소 완료 조건은 필요한 조건 입력을 제공하거나 해당 기술의 미지원/수동 계산 조건을 구체적으로 표시하는 것이다.

근거: `src/js/02-engine.js`의 위력 0 조기 종료, `src/js/03-10-calc-state.js`의 일반 계산 불가 메시지. [도구별 내던지기 위력](https://github.com/smogon/pokemon-showdown/blob/master/data/moves.ts#L5724), [비축 횟수별 토해내기 위력](https://github.com/smogon/pokemon-showdown/blob/master/data/moves.ts#L17623).

## 확인된 안정 영역

- 무효·생존 효과 안내와 피해 산출 분리, 직접 피해 보정 및 생존 후 회복.
- 독립 난수 기반 확정·난수 KO, 정수 HP, 도구 소비·제거 순서.
- 앞서 지원한 연속기·총대장·성묘·순풍·행동 순서 조건과 자동/수동 위력 복원.
- 결과 카드 및 모바일 요약의 예외·확률 표시와 반응형 배치.

이번에 계산기 완료 검사 36개와 결정력 정책 검사 77개를 재실행하여 통과했다. 집중 브라우저 검사도 58개 통과했다. 이전 전체 검사 1,250개 통과와 전체 브라우저 85개 통과 기록은 유지되지만, 새로 확인한 특수 기술의 정확성을 검증한 근거로 사용할 수는 없다. 기존 건너뜀 17개는 현재 Champions 빌드에 없는 기술·도구·포켓몬 사례였다.

## 다음 메뉴로 넘어가기 위한 범위

위 세 항목의 계산 또는 명시적 제한 처리를 완료하고 해당 입력·결과 회귀 검사를 추가한 뒤, 형태 역계산으로 넘어가는 것을 권한다. 여러 세팅 저장·내구 형태 동시 비교 같은 편의 기능은 이 전환을 막을 항목이 아니다.

지원 현황 문서에도 정리가 필요하다. `docs/damage-calculator-coverage-matrix.md`는 이미 구현된 배터리·프렌드가드·파워스폿을 아직 보류로 표시한다. 오로라베일·매직룸·원더룸 및 일부 아군 중첩 보정은 별도 전용 입력의 제한 사항으로 관리해야 한다. 보호기·상대 행동·잔여 피해를 자동으로 재현하지 않는 것은 합의된 계산 범위에 따른 정상 동작이다.

추가 재현 결과: `docs/calculator-readiness-probes.json`. 현재 수록 공격 기술 324개 중 기본 위력 0이면서 기존 가변/고정 규칙에 연결되지 않은 항목은 카운터류 4종과 내던지기·토해내기였다. 이것은 모든 기술 조합의 정확성을 전수 입증한 결과가 아니라 누락 후보를 찾기 위한 데이터 점검이다.
