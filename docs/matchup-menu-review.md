# 상성표·타점 체크 완성도 검토

2026-09-13. `d05592c` 이후 로컬 세부조정·도감 보완이 반영된 프로젝트를 기준으로 검토했다. 상성표 제품 코드는 이번 검토에서 변경하지 않았다.

## 목적과 결론

방어 상성은 파티의 타입별 약점·저항·무효 분포를, 타점 체크는 내 공격 기술의 타입 분포를 보여 주면 된다. 대미지·스피드·대전 승패를 이 메뉴에서 다시 계산할 필요는 없다.

기본 표·파티 불러오기·폼·특성 선택·기술 입력은 갖춰져 있다. 다만 **요약 평가의 의미, 특성·기술의 적용 범위, 입력 상태와 모바일 선택창**을 보완해야 현재 용도로 마무리할 수 있다.

## 유지할 기능

- 6개 파티 슬롯과 파티 저장 데이터 불러오기.
- 선택한 폼·특성을 기준으로 방어 타입 상성 표시. 부유·저수 등 타입 무효 특성은 구분해 표시.
- 포켓몬별 최대 4개 공격 기술 입력과 특성에 의한 공격 타입 변경.
- 같은 포켓몬의 같은 타입 기술은 중복 집계하지 않음. 불꽃 기술 2개를 한 포켓몬이 보유하면 불꽃 보유 수 1, 두 포켓몬이 각각 보유하면 2로 집계.
- 빈 비교 열 생략과 좁은 화면의 표 가로 스크롤 안내.

## 보완 사항

### 1. 방어 요약을 마릿수에 흔들리지 않는 분포 정보로 변경

모두 불꽃을 1배로 받는 실제 수록 포켓몬으로 구성했을 때, 3마리의 점수는 3·‘안전’, 6마리는 6·‘일관성’이다. 약점 0, 저항 0이라는 구성 비율은 같지만 배율 합계에 고정 임계값을 적용해 등급이 바뀐다.

현재 표의 숫자 ‘일관성’만으로는 약점이 겹친 것인지, 모두 등배인지, 한 마리에게 4배 약점이 있는지 파악하기 어렵다. 자세한 수는 셀의 마우스 안내에만 들어 있다.

**권장:** `약점 2 / 반감 1 / 무효 1`처럼 수와 해당 포켓몬을 직접 표시한다. 필요하면 `4배 약점 있음`, `반감·무효 보유 포켓몬 없음`, `약점 집중`을 근거와 함께 보여 준다. 단일 합계의 ‘안전’ 판정을 대체하는 편이 메뉴 목적에 맞다.

싱글 63 활용을 위해서는 추후 전체 6마리를 유지한 채 선출 3마리를 선택해 같은 표를 볼 수 있으면 편리하다. 이는 기본 오류 수정과 구분되는 편의 개선이다.

근거: `defenseTypeProfile`, `defenseScoreLabel`, `renderDefenseScoreCell`.

### 2. 특성 반영 범위를 일관되게 표시

현재는 타입 무효만 반영한다. 메가이상해꽃의 두꺼운지방은 선택돼 있어도 불꽃·얼음이 2배로 표시된다. 같은 프로젝트의 대미지 계산기는 두꺼운지방의 반감을 적용한다. 재현 조건의 화염방사 피해는 특성 적용 48~57, 특성 없음 96~114였다.

타입 자체의 2배는 맞지만, 부유·저수는 적용하는 표에서 다른 방어 특성을 생략하면 ‘선택한 특성까지 반영한 방어 성능’으로 오해할 수 있다.

**권장:** 타입 기본 배율과 확정적으로 적용되는 특성 보정을 함께 보여 준다. 예를 들어 `타입 2배 × 두꺼운지방 0.5 = 1배`. HP·날씨·피격 여부처럼 추가 조건이 필요한 효과는 조건부임을 따로 명시한다. 한 턴 공방이나 모든 전투 상태를 추가할 필요는 없다.

도구는 현재 메가폼 전환에만 사용되고 방어 조건으로 저장·입력되지 않는다. 도구를 반영하지 않는 범위도 명시해야 한다. 특성 보정을 추가하면 1.5·0.75 같은 배율이 생길 수 있으므로, 기존의 고정 배율 사전과 집계도 함께 정리해야 한다.

근거: `matchupAbilityTypeImmunity`, `matchupDefenseEffect`, `data/overrides/ability-mechanics.json`.

### 3. 타입 분포와 상대별 실제 약점 타점을 구분

- 가뭄 메가리자몽Y의 웨더볼을 선택해도 노말로만 집계된다. 현재 메뉴에는 날씨 조건이 없으며 계산기의 쾌청 조건에서는 불꽃으로 바뀐다.
- 프리즈드라이는 얼음 기술이므로 **공격 타입 분포에서 얼음으로 세는 것은 맞다.** 그러나 상대별 타점 요약은 일반 타입표만 사용해서 메가갸라도스에 대한 2배 타점을 놓친다. 일반 얼음 상성은 0.5배지만 현재 계산기의 프리즈드라이는 2배로 계산된다.

**권장:** 날씨·필드에 따라 타입이 바뀌는 기술에는 간단한 기준 조건 선택이나 조건부 표시를 제공한다. 상대별 타점 요약을 유지한다면 프리즈드라이·플라잉프레스 같은 기술 고유 상성과 대상 특성의 적용 범위도 구분한다. 단순 보유 타입과 특정 상대의 약점을 찌르는 기술은 같은 기준으로 판정할 수 없다.

근거: `coverageMoveType`, `renderMatchupMeta('coverageChecks')`, 계산기의 `getMoveEffectiveness`와 기술 타입 결정 단계.

### 4. ‘안전·위험 메타’ 표현을 실제 제공 정보에 맞게 변경

위력 35의 회오리불꽃 하나만 선택해도 메가핫삼은 불꽃 4배 약점을 찌를 수 있다는 이유로 내부 ‘안전’ 판정을 받아 주의 목록에서 사라진다. 이는 그 포켓몬을 이기거나 안전하게 상대할 수 있음을 입증하지 않는다.

방어 쪽 주의 포켓몬도 상대의 실제 기술배치가 아닌 **그 포켓몬의 자체 타입**으로만 분류된다. 참고 상대 목록은 `meta-threats.json`에 고정된 방어 26개·타점 23개이며, 현재 사용률을 가져오는 자료가 아니다. 현재 목록의 ID 연결 누락은 없다.

**권장:** `4배 타점 보유`, `2배 타점 보유 포켓몬 2마리`, `약점 타점 미보유` 같은 사실 표현을 사용한다. ‘안전’이라는 이유로 숨기기보다 무엇을 보유하고 무엇이 부족한지 보여 준다. 패널은 ‘참고 상대’ 등으로 이름과 분석 범위를 명확히 하고, 현재 메타 순위처럼 표현하지 않는다.

근거: `coverageThreatGrade`, `renderMatchupMeta`, `data/overrides/meta-threats.json`.

### 5. 입력 부족과 실제 미보유를 분리

포켓몬 3마리를 선택하고 기술을 전혀 입력하지 않아도 18타입×4열의 72개 셀이 전부 `coverage-miss`로 표시된다. 반대로 포켓몬 1마리와 기술만 입력하면 본문은 ‘3마리 이상’ 안내인데 옆의 상대별 진단은 이미 출력된다.

**권장:** 기술 미입력은 ‘입력 전’, 일부 입력은 ‘입력한 기술 기준’으로 안내한다. 본문과 요약의 표시 조건을 맞춘다. 파티를 구성 중에도 기본 타입표는 1~2마리부터 확인할 수 있도록 하고, 파티 전체 판단은 입력 범위를 명시한다.

### 6. 모바일 선택창과 타점 입력 접근성 보완

실제 375px·320px 화면에서 폼·특성 선택창의 너비가 33px, 패딩을 제외한 글자 표시 공간이 0px로 측정됐다. 드롭다운 화살표만 남아 선택한 폼·특성을 읽을 수 없다. 모바일 규칙이 `grid-area: config` 뒤에 `grid-column: auto`를 지정하는 부분을 포함해 배치를 수정해야 한다.

페이지 자체의 가로 넘침이나 자동 축소는 없고 표의 가로 스크롤 안내는 작동한다. 따라서 가로 넘침 검사만으로 이 문제를 찾을 수 없다.

같은 3마리 입력의 밝은 테마 검사에서 방어 모드는 critical/serious/moderate 위반이 없었지만, 타점 모드는 기술 입력 12개의 `aria-expanded` 누락과 빈 카드 안내 3개의 글자 대비 부족이 검출됐다. 선택값의 실제 표시 공간, 키보드 입력 상태, 안내 글자 대비를 보완해야 한다.

## 확인 자료와 마무리 기준

- 기존 `npm run state:matchup`: **17개 검사 통과**. 폼·무효 특성·기본 집계 중심이며 위 요약·조건부 타점·모바일 선택창 문제를 검사하지 않는다.
- 현재 함수 재현: `scripts/matchup-menu-review.mjs` → [matchup-menu-review-probes.json](matchup-menu-review-probes.json).
- 실제 브라우저 검토: `scripts/matchup-browser-review.mjs` → [matchup-browser-review.json](matchup-browser-review.json). 이 스크립트는 발견된 접근성 위반을 기록하며, 실행 성공이 접근성 통과를 의미하지 않는다.
- 이번 검토는 로컬 데이터·동작 검증이며 외부 최신 메타나 레귤레이션 전수 대조가 아니다.

위 여섯 항목을 보완하고 3마리·6마리 비교, 특성 적용, 조건부·특수 상성 기술, 미입력 상태, 모바일 선택값을 확인하면 요청한 타입 기반 파티 보조 메뉴로 마무리할 수 있다.
