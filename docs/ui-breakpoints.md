# UI breakpoint policy

이 문서는 UI 반응형 CSS가 사용하는 viewport breakpoint의 의미와 사용 규칙을 정의한다.
`scripts/css-structure-check.mjs`가 아래 값 이외의 breakpoint 유입을 차단한다.

## Breakpoint map

| 최대 폭 | 역할 |
| ---: | --- |
| 1759px | 광고 레일을 제거하고 단일 콘텐츠 셸로 전환 |
| 1280px | 넓은 도구 페이지와 결과 그리드 압축 |
| 1120px | 계산기 능력치·결과 열 축소 |
| 1100px | 세부조정·역계산 주/보조 패널 재배치 |
| 960px | 계산기 양측 패널을 한 열로 전환 |
| 860px | 헤더와 중간 폭 도구 레이아웃 압축 |
| 760px | 공통 태블릿/모바일 도구 레이아웃 전환 |
| 720px | 헤더·파티 프리셋 모바일 배치 전환 |
| 680px | 계산기 상세 편집기를 모바일 카드형으로 전환 |
| 620px | 계산 결과와 필드 제어의 좁은 화면 보정 |
| 560px | 공통 패널 여백과 제어행 축소 |
| 520px | 일반 휴대전화 폭의 카드·도감·도구 재배치 |
| 430px | 좁은 휴대전화 헤더와 세부 제어 보정 |
| 380px | 최소 지원 폭의 능력치·내비게이션 압축 |

`prefers-reduced-motion: reduce`는 viewport breakpoint가 아닌 접근성 예외로 허용한다.

## Rules

1. 새 breakpoint를 추가하기 전에 가장 가까운 기존 역할로 해결 가능한지 확인한다.
2. 계산기 주요 전환은 680px, 공통 도구 페이지 주요 전환은 760px를 기준으로 한다.
3. 한 파일 안에서 동일한 media query를 중복 선언하지 않는다.
4. 320px부터 데스크톱까지 문서 전체 가로 스크롤이 발생하지 않아야 한다.
5. breakpoint 변경 시 `npm run css:structure`와 실제 브라우저 smoke test를 함께 실행한다.
