# UI breakpoint policy

확정 계산기 샘플을 기준으로 전 메뉴가 아래 경계를 사용한다. 반응형 규칙은 공통 부품 또는 해당 메뉴 소유 파일에 둔다.

| 최대 폭 | 역할 |
| ---: | --- |
| 1200px | 광고 레일을 숨기고 콘텐츠 셸 단일 열 사용 |
| 1000px | 계산기 결과·부가 제어의 중간 폭 압축 |
| 900px | 계산기·세부조정·역계산·파티 편집을 한 열로 전환, 상성표 카드 두 열 |
| 700px | 공통 글자·여백·선택창·헤더를 모바일 크기로 조정 |
| 480px | 긴 선택 목록의 열 폭 압축, 상성표 카드·역계산 다음 턴 HP 한 열 |
| 360px | 최소 폭에서 헤더·능력치·비교·결과 여백 조정 |

`hover:hover`는 마우스 상태, `prefers-reduced-motion:reduce`는 모션 접근성에만 사용한다.

1. 새 경계보다 기존 부품의 유연한 폭과 배치를 먼저 사용한다.
2. 한 파일 안에서 동일한 media query를 중복 선언하지 않는다.
3. 320px부터 문서 전체에 가로 스크롤이 생기지 않아야 한다. 종족값·상성표처럼 열 보존이 필요한 표와 선택 목록은 내부 스크롤을 허용한다.
4. 노력치와 랭크는 접지 않는다. 6개 능력치 열을 유지한다.
5. 경계를 바꾸면 `npm run css:structure`, `npm run css:cascade`와 실제 화면 검사를 실행한다.

최종 공통 화면 검사는 320, 375, 390, 700, 768, 900, 901, 1000, 1440px에서 라이트·다크 테마를 검사한다. 메뉴별 추가 상태는 각 전용 브라우저 검사에서 확인한다.
