# 계산기 보완 항목 재분석

검토일: 2026-09-08. 대상은 `94063136a69f2916a1de56f4520ccbbf738627b4` 기반의 현재 수정 작업 사본이다. 이번에는 분석과 진단 자료만 추가했다.

후속 구현 결과는 [계산기 보완 결과](calculator-completion-review.md)에 기록했다. 아래 내용은 수정 전 진단이다. 구애머리띠 사례는 현재 수록 도구에 해당 ID가 없으므로 실제 선택 가능한 오류 재현이라는 주장을 철회한다. 바디프레스의 일반 공격 도구 보정은 별도 검증용 도구로 확인했다.

## 판단

계산기 보완은 연속기 표시 수정만으로 끝나지 않는다. 기본 보정식, 기술별 피해 산출, 회복을 포함한 타수 계산, 조건 입력, 결과 표시를 순서대로 정리해야 한다. 이전 메뉴 평가 이후 새로 재현한 기본식 오류까지 포함한 후속 평가다.

검토는 현재 수록 포켓몬·기술·도구, 코드, 저장소의 Pokemon Showdown 및 Champions 변경 데이터, Showdown 계산기 공개 구현을 대상으로 했다. 별도 진단 22개를 실행했으며, 그중 현재 포켓몬·기술 데이터에 대상이 없는 2개는 제외했다. 나머지는 데이터 조사·함수 비교·표시 문자열 검사를 포함한다. 20개 버그 또는 20개 테스트 통과를 의미하지 않는다. 새 브라우저 검사는 하지 않았다.

기존 결정력 정책 검사는 이번에도 통과했다. 그러나 새 재현 사례가 그 검사에 포함되어 있지 않았으므로, 기존 통과 결과로 아래 문제를 부정할 수 없다.

## 유지할 계산 범위

| 항목 | 기준 |
| --- | --- |
| 피해 | 입력한 조건에서 기술이 가하는 피해량과 최대 HP 대비 비율 |
| 기합의띠·옹골참·탈 등 | 피해와 KO 타수를 생존·차단으로 제한하지 않고 결과 카드에 설명 |
| 타입·특성·도구의 무효 | 무효 원인을 설명하면서 피해 계산 계속. 무효 배율만 1로 취급하고 다른 배율 유지 |
| 멀티스케일·반감열매 등 | 피해 감소를 실제 산출에 반영하고 설명 |
| 회복 도구 | 공격을 견딘 경우에만 발동 조건·회복량·소비 여부를 타수 계산에 반영 |
| 난수 | 피해 난수와 해당 기술의 타격 횟수 분포. 명중률·마비 행동불능 등을 곱한 승률이 아님 |
| 1타라는 표현 | 기술 1회 사용. 연속기의 개별 타격 수와 구분 |
| 반복 공격 | 현재 기준은 같은 세팅의 공격을 반복하며 상대 HP와 열매 소비·회복을 갱신. 상대 행동과 일반적인 턴 진행은 하지 않음 |

사용자가 확정한 위 기준을 다시 질문할 필요는 없다. 다만 기술 자체의 실패 조건이나 같은 기술 안에서 후속 타격의 피해를 바꾸는 효과는 아래처럼 별도 항목으로 정리해야 한다.

## 2순위: 기술 1회 안의 연속기 처리

### 재현된 오류와 근사

- **표시 피해와 KO 계산 불일치:** 메가캥카 냉동펀치 → 풀 HP 멀티스케일 망나뇽은 표시용 90~107, KO 내부 타격별 계산 합계 108~129다. 오카열매 핫삼 사례도 표시용 85~102와 내부 합계 102~123으로 다르다. 내부 합계가 독립적인 게임 실측 정답이라는 뜻이 아니라 앱 내부 불일치의 근거다.
- **트리플악셀 평균 위력 처리:** 위력 40을 3번 반복한다. 알로라 나인테일 → 잠만보에서 현재 75~90, 위력 20·40·60을 개별 산출한 합계는 74~89다. 평균 위력은 반올림과 타격별 보정 때문에 같은 결과를 보장하지 않는다.
- **집단구타 근사:** 파티 정보 없이 위력 10의 단발 피해로 처리한다. 참여 포켓몬 수와 각 참여자의 종족 공격력에 따른 타격별 위력이 반영되지 않는다. 현재 리자몽 사례는 5~7의 단발 피해다.
- **표시 타격 수 불일치:** 스킬링크로 실제 계산은 5회인데 카드에는 기본 기술의 ‘2~5타’가 표시된다.

근거: `src/js/02-engine.js:467`, `:470`, `:1103`, `:1220`; `src/js/03-50-calc-results.js:282`. 타격별 위력은 저장소 `data/moves.ts`의 트리플악셀·집단구타와 [공개 계산기 구현](https://github.com/smogon/damage-calc/blob/master/calc/src/mechanics/gen789.ts)을 대조했다.

### 필요한 구현 범위

한 번 산출한 타격별 분포에서 표시 피해·최소/최대·타수 확률을 모두 구해야 한다. 스킬링크·속임수주사위에 따른 횟수와 반감열매 소비, 풀 HP 보정이 풀리는 시점을 포함한다. 부자유친 추가타의 25% 보정 위치와 반올림도 함께 대조해야 한다.

지구력·깨어진갑옷처럼 **같은 기술의 후속 타격 피해를 바꾸는 효과**는 별도로 적용 범위를 정리해야 한다. 현재 일반 랭크 자동 변화는 반복 계산에 포함되지 않는다. 이것을 모든 턴의 전투 시뮬레이션으로 확장할 필요는 없지만, 연속기 총 피해의 정확성을 주장하려면 같은 기술 내부에서 생기는 직접적인 피해 변화는 다뤄야 한다.

트리플악셀의 명중 실패 확률을 일반 KO 확률에 자동 합산하는 것은 이번 목적의 필수 기능으로 보지 않는다. 선택한 타격 수가 명중했을 때의 피해를 계산하고 그 가정을 표시하면 된다.

## 3순위: 회복을 포함한 확정·난수 타수

### 유지할 부분

독립 피해 난수를 누적해 타수를 구분하는 기본 구조와 먹다남은음식·자뭉열매·오랭열매의 생존 후 회복 처리는 이미 있다. 공격이 즉시 KO를 내면 회복하지 않는 기준도 유지한다.

HP 100에 피해 45~55는 회복이 없으면 난수 2타다. 정확한 확률은 실제 난수 분포로 계산해야 한다. 최소 피해 50이고 최대 100 미만이면 회복 없이는 확정 2타다. 같은 피해 50이라도 먹다남은음식이 있으면 100 → 56 → 12 → KO로 확정 3타다.

### 재현된 누락

**자뭉열매 + 볼주머니의 추가 회복이 빠진다.** 검증용 HP 100·매회 피해 70에서 현재 확정 2타로 표시한다. 열매 25와 볼주머니 33을 반영하면 생존 HP가 88 → 18 → KO이므로 확정 3타다. 이 예는 정해진 피해·HP로 회복 로직을 분리한 검증 사례이며 실제 특정 세팅의 피해 범위라는 뜻은 아니다.

볼주머니의 열매 섭취 시 추가 회복은 [Showdown 특성 구현](https://github.com/smogon/pokemon-showdown/blob/master/data/abilities.ts)에 정의되어 있다. 현재 앱 `hkoLabel`에는 해당 처리가 없다. 근거: `src/js/02-engine.js:1436` 부근.

### 완료 조건

- 회복 도구 × 볼주머니·숙성·긴장감·서투름 등 관련 특성 조합을 확인한다.
- KO 뒤 회복 없음, 발동 HP 경계, 회복량 내림, 최대 HP 상한, 열매 1회 소비를 확인한다.
- 연속기에서는 타격 사이의 회복과 기술 사용 사이의 회복을 구분한다.
- 결과에 적용한 회복 도구·특성과 현재 HP 기준을 표시한다.
- 회복을 이기지 못해 KO가 불가능한 상태와 탐색 한도인 ‘10타 초과’를 구분할 수 있도록 개선한다. 현재 후자는 계산 한도 표시다.

현재 수록 도구 중 기본 회복 규칙이 있는 것은 먹다남은음식·자뭉열매·오랭열매다. 큰뿌리·조개껍질방울은 상대가 공격하거나 흡수 기술을 사용해야 회복량이 정해지므로, 방어측이 자동으로 매번 회복하는 도구로 넣어서는 안 된다.

## 5순위: 무효·조건 미충족 안내를 완성하기

- **무효 안내 누락:** 습기 상대 대폭발, 테일아머 상대 신속은 피해 계산이 진행되지만 무효 설명은 비어 있다. 피해를 계속 산출하는 것은 사용자 기준에 맞고, 설명이 없는 것이 문제다.
- **조건 미충족이 미설정으로 표시:** 상대 도구가 없는 폴터가이스트는 결과가 `null`이 되어 카드에 ‘기술 미설정’이 나온다. 선택한 기술명과 ‘상대 도구 없음’ 등 원인을 남겨야 한다.
- 기술 자체의 실패 조건까지 무조건 무시할지는 기존에 명시적으로 확정된 정책과 구분한다. 우선 선택 상태를 잃지 않게 하고, 조건을 가정해 계산할 수 있는 입력을 마련하는 것이 적절하다.
- 타입 무효를 제외한 계산 배율과 실제 무효 원인이 동시에 보이도록 유지한다. 일반 피해 감소 효과는 실제 적용된 타격과 배율을 설명한다.

근거: `src/js/01-core.js:430`, `src/js/02-engine.js:710`, `src/js/03-50-calc-results.js:35`, `:227`.

전수 점검은 특성·도구 ID마다 ‘데이터에 있음’을 확인하는 것으로 끝나면 안 된다. 타입·기술 태그 무효, 우선도 차단, 특정 기술 차단, 생존, 직접 감소, 회복으로 나눠 실제 결과 카드까지 도달하는지 확인해야 한다.

## 6순위: 결정력 표시·추천·설명을 실제 계산과 통일하기

### 재현된 문제

- **추천이 2타 확률을 직접 비교하지 않음:** 검증용 16개 피해 분포 A는 49가 15개·51이 1개, B는 45가 1개·55가 15개다. HP 100에서 둘 다 난수 2타/확정 3타지만 2타 확률은 A 12.1%, B 99.6%다. 현재는 최소 피해가 높은 A를 추천한다.
- **결정력 수치의 능력치 불일치:** 야도란 바디프레스에서 방어 투자 0 → 32로 피해가 92~110 → 116~138로 증가해도 기술 목록의 결정력은 7,600으로 동일하다. 별도 추정 함수가 공격 실수치를 사용하기 때문이다.

근거: `src/js/03-50-calc-results.js:117`, `src/js/03-20-calc-combobox.js:11`.

### 개선 방향

- 같은 필요 타수 안에서는 해당 횟수의 누적 KO 확률을 먼저 비교한다. 현재 추천 목적은 명중률 등을 합친 최선의 행동이 아니라 입력 기준의 결정력 비교다.
- 기술 목록의 결정력, 카드의 피해, 모바일 요약이 같은 조건·기술 분류·사용 능력치를 참조하도록 한다.
- ‘난수 2타 68.8%’처럼 확률을 중심으로 표시하고 필요하면 확정되는 타수도 함께 제공한다. 고난수·저난수라는 표현을 붙인다면 구간 기준을 일관되게 정한다.
- 연속기 ‘5회 적중’과 기술 사용 기준 ‘확정 2타’를 분리한다. 회복 전 잔여 HP와 회복을 반영한 타수도 구분한다.
- 반동·흡수는 핵심 결정력 외의 보조 표시다. 유지한다면 실제 잔여 HP 상한, 돌머리·매직가드·큰뿌리 등 관련 효과와 이론값/실제 회복량의 의미를 별도 확인해야 한다. 현재 총 피해 비율만으로 표시하는 부분이 있다.

## 완료 판정 기준

1. 위에서 재현한 기본식·도구·특성 오류가 정답 대조에서 해소된다.
2. 표시 피해와 KO 확률이 같은 타격별 피해 분포를 사용한다.
3. 회복이 없는 난수 경계와 회복 도구 조합의 타수 결과가 일치한다.
4. 필요한 조건을 UI에서 지정할 수 있고, 지정하지 못한 조건은 결과에 명확히 드러난다.
5. 무효·생존 예외는 피해 산출을 막지 않으면서 누락 없이 설명된다.
6. 결정력·추천·모바일 요약이 실제 계산 조건과 맞는다.
7. 현재 수록 기술·특성·도구를 상호작용별 검증표로 관리한다. 아직 지원하지 않는 항목은 근사값을 정확한 값처럼 제시하지 않는다.

우선 구현 묶음은 **기본 보정식 → 연속기 계산 통일 → 회복·타수 검증 → 조건 입력·결과 표시**가 적절하다. 다른 메뉴의 기능 확장은 이 계산기 작업과 분리한다.
